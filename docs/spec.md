# SkyRaid: Titan Skies — ゲーム仕様書 v0.1

## 1. コンセプト

- ブラウザで動く、見た目が綺麗なアーケード寄り3Dフライトシューティング
- 1人: ミッションを遊んで報酬を集め、機体を強化する
- 2〜4人: PvPドッグファイト、巨大怪獣との協力レイド
- 10分遊んで気持ちいい「飛行感」が最優先。リアル志向のシミュレーターではない

## 2. 対象環境

- デスクトップブラウザ（Chrome / Edge / Safari / Firefox 最新）
- スマホブラウザ（iOS Safari / Android Chrome）: タッチ操作対応、画質は自動で落とす
- 同時プレイ 1〜4人
- 運用コストはゼロを目標（静的配信 + P2P）

## 4. 飛行モデル（アーケード）

- 操作: ピッチ / ロール / ヨー / スロットル。失速あり、エンジン出力で回復
- 速度域: 最低 80 / 巡航 250 / 最高 400（単位はゲーム内の m/s 相当、`data/aircraft.ts` で定義）
- 地面・海面に衝突で撃墜。高度上限で押し戻し
- アフターバーナー: 一時加速。ゲージ消費
- 機体ごとに「速度 / 旋回 / 耐久 / 積載」の4パラメータで差をつける（3-4。「7. 成長と経済」）
- オートレベル（手を離すと水平に戻る）を初期ONにし、設定でOFF可能

#### 決めた数値の意味（1-1。値は `src/data/aircraft.ts` 初期機 / `src/data/flight.ts`）

- 速度は進行方向のスカラー。横滑りなし。姿勢はクォータニオン（前方 -Z・上 +Y・右 +X）
- `speed.stall` 80: これを下回ると失速。`stall.range` 30 下（50）で失速の効果が最大
- `speed.cruise` 250: 起動・リセット時の速度。スロットル初期値はこれを水平で保つ値（約 0.70）
- `speed.idle` 60: スロットル 0 で落ち着く速度。失速より低いので、絞り続けると失速する
- `speed.military` 330: スロットル 1 で落ち着く速度
- `speed.afterburner` 400: アフターバーナー中に落ち着く速度（最高速度）
- `speed.limit` 460: 降下で到達できる絶対上限
- `speed.response` 0.45 / `afterburnerResponse` 0.9: 目標速度へ近づく速さ（1/秒）
- `speed.maxAccel` 15 / `afterburnerMaxAccel` 35 / `maxDecel` 20: エンジンによる加減速の上限（m/s²）。加速上限が重力の効き（約 34）より小さいので、垂直上昇は必ず減速して失速に至る
- `gravitySpeedScale` 3.5: 重力（9.8）が速度に効く倍率。上昇で減速・降下で加速を誇張する（巡航から 30° 上昇 2 秒で約 −23 m/s）
- `rates.pitch` 75 / `roll` 200 / `yaw` 22: 旋回係数 1.0 のときの最大角速度（度/秒）。巡航で宙返り 1 周が約 5 秒
- `turnCurve`: 速度→旋回係数の折れ線。0:0.2 / 80:0.35 / 180:0.9 / 220〜300:1.0 / 400:0.7 / 460:0.55（低速で鈍く、巡航付近で最大、超高速で再び鈍る）
- `rates.rollSpeedSensitivity` 0.5: ロールが速度の影響を受ける割合（ピッチの半分）
- `rateResponse` 9: 入力から角速度が立ち上がる速さ（1/秒）。約 0.1 秒の「重さ」
- `stall.minAuthority` 0.3: 失速最大時の操舵の効き
- `stall.noseDropRate` 55: 失速最大時に機首が真下へ向く角速度（度/秒）
- `stall.sinkSpeed` 18: 失速最大時の沈下速度（m/s）
- `autoLevel.gain` 1.2 / `maxRate` 50: ピッチ・ロール入力がないとき、バンク角×1.2（最大 50 度/秒）で水平に戻す。45° からおよそ 3 秒
- `autoLevel.maxNoseVertical` 0.85: 機首が真上・真下に近い（約 58° 以上）ときはオートレベルを効かせない
- `bankTurnRate` 12: バンク 90° で機首が自然に横へ向く角速度（度/秒）
- `afterburner.durationSeconds` 6 / `rechargeSeconds` 10 / `rechargeDelaySeconds` 1 / `restartThreshold` 0.15: 満タンで 6 秒使える。離して 1 秒後から 10 秒で満タン。空にしたら 15% まで回復するまで再点火できない
- `ceiling.start` 3000 / `end` 3500 / `pushRate` 60: 3000m から機首を押し下げ始め、3500m で最大・それ以上は上がれない
- `groundAltitude` 0 / `spawn.position.y` 300: 地表（島の上は地形の高さ、海の上は海面 0。1-3 から）以下で衝突し、墜落地点の地表から 300m 上空に初期姿勢でリセット。`groundAltitude` は地形を渡さないとき（テスト等）の地面の高さ
- `throttleRate` 0.6: Shift / Z でスロットルが 1 秒に変わる量
- 操作設定の切替: ポーズメニューの設定の「操作」（4-11。下の「操作設定」）。URL の `?autolevel=off`（オートレベル OFF）・`?invert`（ピッチ反転。W = 機首上げ）は残し、指定した項目は設定より優先する
- 開発用: `?skipTitle` でタイトル・モード選択を飛ばして起動直後からフリーフライト（他のパラメータと併用可）

#### タッチ・ゲームパッドの決めた数値（1-5。値は `src/data/touch.ts` / `src/data/gamepad.ts` / `src/data/input.ts`）

- タッチ操作は主ポインタが指（`pointer: coarse`）の端末で自動表示。ポーズメニューの設定「タッチ」で 自動 / 表示 / 非表示 を選べ、セーブデータの設定に保存（3-1。それまでは localStorage の `skyraid.touchControls`）
- 仮想スティック: 画面左 45%・上 25% より下のどこに触れてもそこが中心。指 64px 移動で最大、デッドゾーンは半径の 12%（約 8px）。デッドゾーンの外側は 0〜1 に引き伸ばす（半径方向）
- ボタン: 64px（機銃のみ 80px）、間隔 12px。ヨーボタン 56px。画面端から 16px + safe-area
- スロットル: 幅 56px、高さは画面の 55% と 240px の小さい方。触れた位置の値（上端 = 1）になり、離しても保持。キーボード等で変えたスロットルも表示に反映
- ゲームパッド: スティックのデッドゾーン 0.15（半径方向）、トリガー 0.05。接続（`gamepadconnected`）で自動有効、最初に見つかったパッドを使う
- 連続値をボタン扱いするしきい値: 0.5 以上で押下、0.35 未満で離す（ヒステリシス）
- 系統（キーボード・タッチ・パッド）の軸の値は足して ±1 で頭打ち。キーボードは ±1 のまま

#### 操作補助（4-12。値は `src/data/assist.ts`。設定で OFF にでき、OFF のときは 4-11 までと同じ挙動）

実機のスマホで「操作が難しく敵を捉えられない」と評価されたので足した。飛行モデルの数値は変えず、入力・判定・カメラ・HUD で補う。

- ポーズメニューの設定に「エイムアシスト」「ターゲットカメラ」「HUD 補助」の ON/OFF（初期はすべて ON）。セーブの `settings.assist` に保存
- 「最後に操作した入力系統」（`Input.lastDevice`）: キーを押すとキーボード、タッチ・パッドの値が 0 より大きくなるとその系統。エイムアシストと機銃の判定の拡大は、タッチ・パッドのときだけ
- エイムアシスト（`src/combat/aim-assist.ts`）: 選択中の対象（機銃の射程内なら予測照準点）が機首から ±8° 以内なら、機首をそちらへ向ける向きにピッチ・ヨーの入力を足す。足す量は角度の差に比例（4° で最大）し、最大 0.25（入力の 25%）。8° の手前 2° で 0 へ弱める。操縦の入力（ピッチ・ロール・ヨーの絶対値の最大）が 0 なら足さない（勝手に追わない）。0.2 未満では入力に比例して弱める。ピッチ反転の設定では補正も反転
- 機銃の当たり判定: タッチ・パッドで エイムアシスト ON のとき、自機の弾に対する対象の半径を 1.3 倍（敵機 6m → 7.8m、的 8m → 10.4m）。敵の弾・ミサイル・ロケットは変えない
- ターゲットカメラ（`src/render/camera-focus.ts`。追従カメラのときだけ）: 選択中の対象が画面の端に近づく（視線から「画面の半分の画角（縦・横の小さい方）− 6°」を超える）と視線を対象の側へ回し始め、「+ 10°」で最大 15°。回す量は 3/秒でなめらかに追う。回した視線で自機が画面の縦・横の端から 8° 内側より外に出るなら、回す量を減らす（二分法）。正面の対象・真後ろの対象では回さない
- HUD 補助（`src/ui/hud-assist.ts`）:
  - 画面中央の○（半径 74px、狭い画面 54px）の外周に、選択中の対象の向き（機体から見た向き。画面の上から時計回り）へ太い線（7 × 26px）。対象が画面の外にいる間は、線の外側に「機首（進行方向）と対象のなす角」と距離（例「35° 1.2km」。画面内ではひし形の下に距離が出ているので出さない）。なす角が 3° 未満なら出さない
  - 選択中の対象の距離の色: 近づいている（相対速度の視線方向の成分が 5 m/s より大きく縮む）は白、離れている（5 m/s より大きく伸びる）は橙。間は前の色のまま。○と線・文字、ひし形の下の距離の両方
  - レーダー: 直径を 1.3 倍（156px、狭い画面 114px。設定によらず）。敵機の点に高度差（自機より 150m 以上高ければ点の上に ▲、低ければ下に ▼）
  - BEHIND: 敵機が自機の尾部から 60° 以内・1500m 以内にいると、レーダーの上に赤い「BEHIND」を点滅（0.4 秒周期）し、レーダーのその点を点滅（0.3 秒周期）

#### 操作設定（4-11。値は `src/data/controls.ts`、変換は `src/core/control-settings.ts`、画面は `src/ui/control-settings.ts`）

- ポーズメニューの設定の「操作」。変えるとすぐ効き、セーブの `settings.controls`（v5）に保存する（スライダーは離したときだけ保存）。初期値は 4-10 までの挙動と同じ
- スティック感度 0.6〜1.6（0.1 刻み、初期 1.0）: タッチのスティック・パッドの左スティックのピッチ・ロールの値に掛け、1 で頭打ち（`Input.axis`）。1 未満では倒しきっても 1 に届かない。キーボード・ヨー・スロットルには掛けない。飛行モデルの数値は変えない
- デッドゾーン 5〜25%（1% 刻み、初期 12%）: タッチのスティックだけ（パッドは 15% のまま）
- ピッチ反転・オートレベル（初期 OFF / ON）: 機体の `FlightModel.options` を書き換える。URL の `?invert` / `?autolevel` があればそちら
- 左右入替（初期 OFF）: タッチのスティックの範囲を右 45% に、スロットルとボタン群を左に。ボタンの並びも鏡にする（機銃が左下）。ヨーボタン・⏸ ボタンはそのまま
- 振動（初期 OFF）: Vibration API で被弾 40ms・自機のミサイル発射 20ms・撃墜 60ms。Android のブラウザだけ（iOS の Safari は API がない。PC の Chrome は関数はあるが振動しないので、User-Agent に Android がなければ「振動（Android のみ。この端末は非対応）」と出して押せない）
- ボタンの大きさ 小 / 中 / 大（0.8 / 1 / 1.2 倍。中が 4-10 までの大きさ）: ボタン・機銃・スロットルの幅・ヨーボタンに掛ける（CSS 変数 `--tc-scale`）。⏸ ボタンの位置もヨーボタンに合わせる
- キー割当（「キー割当 ▼」で開閉）: 主要 12 アクション（機首下げ・機首上げ・左右ロール・左右ヨー・スロットル + / −・機銃・ミサイル・アフターバーナー・フレア）の主キー（WASD 側）を差し替える。矢印キーなど 2 つ目以降の初期のキーは残す。ボタンを押してから割り当てたいキーを押す（待っている間のキーはゲームに渡さない）。Esc で取り消し（Esc は割り当てられない）。ほかのアクション（変えられないターゲット切替・カメラ・ロケット・爆弾・F3・H を含む）と重なったら「⚠ カメラ切替と重複」を出す（割り当てはする。重なったキーは両方のアクションが効く）。「初期の割当に戻す」

### カメラ

- 三人称追従（デフォルト）。速度で画角とカメラ距離が変わる
- C キーで「追従」⇄「固定後方」（スプリングなしで機体に完全追従）を切替

#### 決めた数値の意味（1-2。値は `src/data/camera.ts`）

- 位置・注視点・上方向はそれぞれ別の臨界減衰スプリング（行き過ぎなし）で、機体位置からのオフセットに追従する。固有角振動数 `positionStiffness` 8 / `lookStiffness` 14 / `upStiffness` 5（1/秒）。追従遅れはおよそ 2 / 値 秒（位置 0.25 秒・注視点 0.14 秒・ロール 0.4 秒）
- `distanceCurve`: 速度→後方距離（m）。80:22 / 250:24 / 400:28 / 460:29。巡航で 1-1 と同じ 24m
- `fovCurve`: 速度→垂直画角（度）。80:57 / 250:60 / 400:70 / 460:73。巡航で 1-1 と同じ 60°
- `afterburnerFovBoost` 5 / `afterburnerDistanceBoost` 2 / `afterburnerResponse` 4: アフターバーナー点火中に画角 +5°・距離 +2m を上乗せし、約 0.25 秒で立ち上がる。速度が上がり切る（約 4 秒）前に「速くなった」ことを伝える。最高速 400 で画角 75°
- `height` 6 / `lookAhead` 30: 機体の上方向 6m に置き、機首の前方 30m を見る（機体基準なので宙返り・背面でも崩れない）
- `turnLeadGain` 6 / `turnLeadMax` 8: 旋回中は注視点を「機首が向かう側」へ 角速度（rad/s）× 6m、最大 8m ずらす。巡航の全力ピッチで機体は画面中央から約 20° 下に来る
- `fixed`: 固定後方の距離 24 / 高さ 6 / 注視点 30。画角は速度の折れ線のみ
- `minHeightAboveGround` 3: カメラは地面から 3m より下へ行かない
- `shake.stallAmplitude` 0.25 / `impactAmplitude` 1.2 / `impactDecay` 3 / `frequency` 9: 失速度合いに比例した揺れ（最大 0.25m）、地面衝突で 1.2m の揺れが 1 秒で約 5% まで減衰。振幅を 0 にすると無効
- コックピット視点（フェーズ4以降）
- ミサイル発射後 1 秒間、任意でミサイルカメラ

## 5. 戦闘

### 武装
- 機銃: 弾数無限、熱ゲージ、近距離向け
- 誘導ミサイル: ロックオン制。弾数制限、補給はミッション間
- 無誘導ロケット / 爆弾: 対地・対怪獣向け（2-6。下の「無誘導兵器・地上目標・対空砲」）
- フレア: ミサイル回避。回数制限

#### 機銃の決めた数値（2-1。値は `src/data/weapons.ts` / 的は `src/data/targets.ts` / 演出は `src/data/effects.ts`）

- 操作: 機銃（Space / パッド RB / タッチ GUN）を押している間連射。弾数は無限
- 連射 `fireRate` 15 発/秒。押した瞬間に 1 発目が出る。発射タイミングはステップの途中でも正確に（撃った瞬間からステップ終わりまでの分だけ弾を先に進める）
- 弾速: 機首方向に `muzzleSpeed` 900 m/s + 機体の速度（巡航で約 1150 m/s）。銃口は機体ローカル (0, −0.3, −7.5)
- 射程 `range` 1500m（ワールドでの移動距離）。巡航で約 1.3 秒飛んで消える
- 重力 `gravity` 9.8 m/s²。射程いっぱいで約 8m 落ちる
- ばらつき `spreadDeg` 0.3°（機首方向から最大のずれ）
- ダメージ `damage` 12 / 発（4-12 で 10 → 12。機体・強化の基準値なので loadout の Lv0 も 12）
- 熱ゲージ: 1 発 +1/60（`heat.perShot`）。撃ち続けて 60 発（4 秒）で上限 → オーバーヒート。最後に撃ってから 0.3 秒（`coolDelay`）で 0.4/秒（`coolRate`）で冷え始める（満タンから 0 まで 2.5 秒）。オーバーヒート中は待ちなしで冷え、0.5（`recoverBelow`）まで冷えると解除（約 1.25 秒）
- 当たり判定: 固定ステップ（60Hz）ごとに、弾の前ステップ位置 → 現在位置の線分と対象の球（半径は対象ごと）の交差。1 ステップ約 19m 進んでもすり抜けない。複数に当たる場合は手前の 1 つ。地面・海面に当たった弾も消える
- 弾はプール（`maxBullets` 256）で使い回す。満杯のときは撃っても弾が出ない（通常の連射では 20 発前後しか同時に飛ばない）

### 敵機AI（2-3）
- 状態: 巡航 → 追尾 → 攻撃 → 回避 → 離脱
- 難易度は反応時間・命中率・ミサイル使用頻度・最大 G で調整

#### 敵機 AI の決めた数値（2-3。値は `src/data/ai.ts`、敵機は `src/data/aircraft.ts` の `ENEMY_FIGHTER`、敵の機銃は `src/data/weapons.ts` の `ENEMY_GUN_CONFIG`）

- 物理はプレイヤーと共通: 敵機も `Aircraft`（1-1 の飛行モデル、オートレベルなし）で飛び、AI は毎ステップ pitch / roll / yaw / スロットル位置 / アフターバーナー / 機銃・ミサイル・フレアの「入力値」を出すだけ（`src/ai/`、Three.js 非依存）
- 判断と操縦: 状態の遷移・発射の判断・相手の見直しは反応時間（`reactionSeconds`）ごと。間の相手の位置は「判断のときの位置 + 速度 × 経過時間」で見積もる。操縦（機首を狙いへ向ける）は毎ステップ
  - 操縦は「狙いが機首から 8° 以上離れていればロールで狙いを頭上に置いてピッチで引く、近ければピッチとヨーで合わせる」。比例（ロール 3・ピッチ 4・ヨー 3 / rad）+ 角速度のダンピング + 狙いの向きの回転速度のフィードフォワード（旋回する相手を遅れなく追う）。下向き（マイナス G）は上限の 30% まで
  - 最大 G: ゲーム内の G = 速度 × ピッチ角速度 / 9.8 が難易度の `maxG` を超えないようピッチ入力を頭打ちにする（初期機のプレイヤーは巡航で約 33G 引ける）
- 巡航（patrol）: 経路点を順に回る（水平距離 500m 以内で次へ）。スロットル 0.7
- 発見 → 追尾: 4500m 以内かつ機首から ±70°、または 1200m 以内（向きによらない）。7000m より離れると見失って巡航へ
- 追尾（engage）: 純追尾ではなく予測位置へ。狙い = 相手の「迎撃の予測時間（自分の速さで直進して追いつく時間、最大 3 秒）後の位置」から相手の進行方向の後ろへ 250m（距離 1000m 未満では距離に比例して 0 へ）。3000m より遠いとアフターバーナー（ゲージ 40% 以上）
- 攻撃（attack）: 1400m 以内・機首と機銃の予測照準点のなす角 25° 以内で移り、1.3 倍の距離・1.8 倍の角度を超えたら追尾へ戻る（行き来しない）
  - 予測照準点はプレイヤーと同じ式（弾速 = 機速 + 900、重力の持ち上げ）+ 相手の加速度（前回の判断からの速度の変化）× `leadAccelWeight` × t²/2。これに狙いのずれ（`aimErrorDeg` の円の中で一様、判断ごとに引き直し）を足した向きへ機首を向ける
  - 機銃: 機首とその向きのなす角が `gunConeDeg` 以内・1100m 以内で撃つ。「撃つ `gunBurstSeconds` → 休む `gunPauseSeconds`」をくり返してオーバーヒートさせない。450m より近いとスロットル 0.35 で追い越さない
  - ミサイル: 敵機もプレイヤーと同じロック（±12°・2500m・1.2 秒）。ロック完了中、判断ごとに `missileChance` の確率で撃ち、撃ったら `missileIntervalSeconds` は撃たない。搭載 `missileAmmo` 発（再出現で満タン）。ミサイル本体の性能はプレイヤーと同じ
- 回避（evade）: 自分を追うプレイヤーのミサイルに気づいたら（判断ごとに `evadeMissileChance`）、または被弾が続いたら（受けたダメージを半減期 1.5 秒で足した値が 20 を超え、判断ごとに `evadeHitChance`）。40% でバレルロール（ロール全開 + 最大の 60% で引く）、60% で急旋回（脅威への向きと真上に直交する向きのうち機首に近い側へ最大 G）。どちらもアフターバーナー。ミサイルに追われている間は判断ごとに `flareChance` でフレア（搭載 `flareCharges` 回、クールダウンはプレイヤーと同じ 2 秒）。3.5 秒続け、ミサイルに追われていれば最大 7 秒まで延ばす。終わったら追尾（見失っていれば巡航）
- 離脱（disengage）: HP が 30% を下回る（1 回の出撃で 1 度だけ）、または追尾・攻撃を続けて 25 秒、相手の後方（尾部から ±50°・1800m 以内）を取れないと判断ごとに 50% で。相手と反対の水平方向へ少し上りながら（上向き成分 0.25）アフターバーナーで 8 秒飛び、追尾（見失っていれば巡航）へ戻る
- 地面の回避: 地表（島の上は地形、海の上は海面）から 150m を切る、または今の降下率のまま 3 秒後に切るなら、どの状態より先に「機首の水平方向 + 上向き 1.5」へ引き起こす（機銃も撃たない）。引き起こしだけは難易度の最大 G が 14 より小さくても 14G まで引く（4-12。rookie 9G・easy 11G では山の斜面で間に合わず衝突したため。normal / hard は変わらない）。島の上で hard 4 機が 3 分戦っても衝突しないことをテストで確認。それでも衝突したら撃墜扱い（撃墜数には数えない）

#### ミッションの仕組み（2-4。ロジックは `src/missions/`、Three.js 非依存）

- ランナー（`missions/runner.ts`）: 固定ステップで、出現物の投入 → 戦域の境界 → 目標の進み具合 → 達成した目標の次を始める → 失敗 / 成功の判定、の順に進める。世界（自機・撃墜数）は `MissionWorld`（`missions/world.ts`。実体は `FlightSession`）を毎ステップ読むだけ
- 進み具合・結果はイベントバスで知らせる（HUD・リザルトが購読）: `objective:activate` / `objective:progress` / `objective:complete` / `boundary:change` / `mission:end` / `mission:abort` / `mission:reward`
- 出現物: 敵機（グループ名・数・難易度・出現位置・巡航経路・狙う相手（プレイヤー / 輸送機優先。2-5）。撃墜されても再出現しない。同時に 4 機まで）/ 的（`data/targets.ts` の出現地点の先頭から数）/ ドローン（軌道の先頭から数）/ 地上目標（グループ・種類・地表の位置・対空砲の難易度。2-5、種類は 2-6）/ 輸送機（グループ・始点・終点。2-5）/ 怪獣（出現位置・歩いて向かう先・撤退する割合。仮実装。2-5）。出現のタイミングは「開始時」「開始から N 秒」「目標 X が始まったとき」「目標 X を達成したとき」
- ミッション中はフリーフライトの的・ドローン・敵機を出さない（定義の出現物だけ）。フリーフライトに戻ると元どおり
- 目標（`missions/objectives/` に 1 種類 1 ファイル）:
  - 撃墜数: 種類（敵機 / 的 / ドローン / 地上目標 / すべて）とグループを指定し、目標が始まってからの撃墜を数える。敵機の地面への衝突も 1 機に数える（再出現しないので、数えないと達成できなくなる）
  - 生存時間: 目標が始まってから N 秒（撃墜されている間は数えない）
  - リング通過: 次のリングだけを順に数える（先のリングを通っても数えない）。判定は「前ステップの位置 → 今の位置」の線分が輪の面を横切り、交点が輪の中心から通過半径以内。向きはどちらから抜けてもよい
  - 護衛（2-5）: グループの輸送機が目的地（水平の円）に入れば達成。進み具合は経路の %（着くまでは 99 で止める）。輸送機を失ったときの失敗は失敗条件「護衛対象の喪失」
  - 破壊（2-5）: グループの地上目標を N 個壊す（出現物の数と同じにすれば全部）。目標が始まる前の破壊は数えない
  - 怪獣（2-5）: 怪獣の全体の HP を指定の割合だけ削れば達成。進み具合は削った %（届くまでは割合 − 1 で止める）。部位 HP はフェーズ6
  - 必須 / 任意。順序は `start`: `withPrevious`（直前と同時）/ `afterPrevious`（それまでの必須目標をすべて達成してから）。任意の目標は次を待たせない
- 成功: 必須の目標をすべて達成。失敗（定義で選ぶ）: 自機撃墜（墜落も）/ 護衛対象の喪失（出ている輸送機のどれかが撃墜された。2-5）/ 制限時間超過 / 戦域離脱。同じステップなら失敗を先に見る
- 終わると画面中央に「MISSION COMPLETE」/「MISSION FAILED」（失敗の理由）を 2 秒出し、そのあとリザルト。その 2 秒もゲームは進む
- 一時停止: ポーズ中はランナーも止まる。中断: ポーズメニューの「ミッションを中断」でミッション一覧へ（報酬・リザルトなし）
- 報酬: 獲得クレジットを `mission:reward` で知らせる。3-2 から `src/progression/mission-rewards.ts` が受けて残高に足し、保存する（成功の `mission:end` でランクと解放も記録）

#### 戦域の境界（2-4。値は `src/data/maps.ts`）

#### 評価と報酬（2-4。式と値は `src/data/ranking.ts`）

- 点数 = min(100, 100 − 時間の減点 − 被弾の減点 + 任意目標の加点)
  - 時間の減点 = 50 × clamp((クリア時間 ÷ 基準時間 − 1) ÷ (2 − 1), 0, 1)（基準時間以内で 0、2 倍で最大 50）
  - 被弾の減点 = 50 × clamp(受けたダメージ ÷ 最大 HP, 0, 1)（墜落は含めない。HP 200 の初期機で 40 受けると −10）
  - 任意目標の加点（3-2）= 10 × 達成した任意目標の数 ÷ 任意目標の数（任意目標のないミッションは 0。今は M3 の「敵機 4 撃墜」と M5 の「敵機 2 撃墜」）。減点を取り返すだけで 100 点は超えない。10 点は 1 ランクの幅（15〜20 点）より小さく、任意目標だけでランクが 2 つは上がらない
- S: 90 点以上 / A: 75 以上 / B: 55 以上 / C: それ未満。失敗・中断はランクなし・報酬 0
- 報酬 = 基本額 × ランク倍率（既定 S ×2 / A ×1.5 / B ×1.2 / C ×1。ミッションごとに上書きできる）

## 9. マルチプレイ

- 方式: PeerJS による P2P。部屋コード（6文字）で接続
- ホストが正。クライアントは入力を送信し、状態を受信して補間表示
- 送信頻度: 入力 30Hz、状態 15Hz。位置・姿勢・速度・HP・弾
- 当たり判定はホスト側で決定。クライアント側は演出のみ
- ホスト切断時はセッション終了（ホスト移行はしない）。クライアントの 10 秒以内の切断は再接続して続ける（5-4）
- 遅延対策: デッドレコニング（速度で外挿）+ スナップ補正

#### P2P の基盤の決めた数値（5-1。値は `src/data/net.ts`、仕組みは `src/net/`。Three.js・DOM 非依存）

- 通信の抽象 `Transport`（`src/net/transport.ts`）: connect / send / onMessage / onPeerJoin / onPeerLeave / close。実装は PeerJS（`peerjs-transport.ts`。公開シグナリングサーバー 0.peerjs.com + Google の STUN。相手ごとに確実・順番どおりの経路と順不同の経路の 2 本）、インメモリ（`MemoryNetwork`。テスト用、遅延・揺らぎ・ロスを設定でき時刻は手で進める）、BroadcastChannel（`local-transport.ts`。`?net=local` で同じブラウザのタブどうし。確認用）
- 部屋（`room.ts` / `client-room.ts`）: ホストが 6 文字の部屋コード（0 / O / 1 / I を除いた英大文字と数字 32 文字）を作り、PeerJS の ID `skyraid-titan-<コード>` で待つ。使用中なら作り直す（4 回まで）。クライアントはコードで接続し join を送り、welcome（名簿・割当 ID 0〜3・ホストのゲーム設定）を受け取る。最大 4 人（満員・開始後・版違いは理由つきで断る）。入力のゆれ（小文字・空白・ハイフン）は受け付ける。参加の待ちは 15 秒
- 切断: クライアントが抜けたら名簿から消して全員に名簿を送り直し、その機体を消す。ホストが抜けたら（自分で退出: 終了の event / 接続が閉じた / 6 秒なにも届かない）全員に「ホストが切断しました」と出してモード選択へ。ping は 1Hz（往復時間の計測と生存確認）
- メッセージ（`protocol.ts`。ArrayBuffer、先頭 1 バイトが種類）: join / welcome / input（クライアント → ホスト、30Hz）/ state（ホスト → 全員、15Hz）/ event（start・end・fire・kill。fire・kill は 5-3 で使う）/ ping。位置は float32、姿勢は smallest-three（15 ビット × 3、6 バイト、誤差 0.01° 未満）、速度ベクトルは 1/16 m/s の int16。state は 1 機 37 バイト
- 入力: クライアントは操作を量子化（各軸 ±127 段階）してから自機に使い、ステップ番号（seq）付きで 2 ステップに 1 回、直近 6 ステップを送る。オートレベル・ピッチ反転の設定も入れる。ホストは最初に 6 ステップ溜めてから seq の順に 1 ステップ 1 つずつ使い（12 を超えたら 2 つずつ）、届かない・切れたステップは直前の操作で埋める。丸ごと間に合わないメッセージが 3 回続いたら溜め直す
- 自機: 手元で先行計算する（操作の遅れなし）。ホストの state の「最後に使った seq」の位置と、同じ seq の自分の記録が 0.5m 以上ずれたら差を足して直す（記録は 128 ステップ）
- 他機: ホストの時刻で 100ms 遅らせ、前後の state を位置はエルミート・姿勢は球面線形で補間。途切れたら速度と加速度で最大 0.5 秒外挿（加速度は 150 m/s² まで）、その先は止める。ホストの時刻は受信の直近 30 個から推定し、毎秒 0.1 秒までの速さで寄せる（0.25 秒を超えたら一度に）
- ホストのゲーム設定（welcome）: マップ `island`・制限時間 300 秒・撃墜数 10（5-3 からロビーでホストが選ぶ）・個人戦・強化の無効 ON・初心者保護 OFF（5-4）
- 開始位置: 島の沖合（0, 800, 4500）に ID 順の横一列、間隔 150m、機首は +Z（海側・島の外向き。操作しなくても 30 秒は山・海面・隣の機体にぶつからない。5-4 の事前修正。それまでは高度 500m・間隔 80m・機首 -Z）。各自がハンガーで選んだ機体・強化で飛ぶ（ホストもその数値で計算する）
- 色: ID 0〜3 が赤・青・黄・緑。機体のアクセント色をその色に、胴体を 30% その色に寄せる（自機も）。他機には名前と距離の名札（10m 単位、1km からは 0.1km 単位）
- ロビー（`src/ui/lobby.ts`）: モード選択の「PvP」→「部屋を作る」/ 部屋コードを入れて「コードで参加」→ ロビー（部屋コード・マップ・参加者の色と名前・ホストの「開始」（2 人以上）・退出）。`?room=XXXXXX` で起動するとタイトルの後に直接参加する
- 飛行中の Esc / ⏸: ゲームを止めないメニュー（続ける / 退出する。退出は確認なしで 1 回で抜ける。メニューはタッチ操作より上）
- `?netdebug`: 飛行中、左下に役割・ID・人数・往復時間・state の受信（送信）回数 / 秒・補間遅延・補間の余裕（最新の state − 表示時刻）・外挿中の機数・自機の補正の回数（ホストは入力の溜め・推測で埋めた数・溜め直しの回数）
- 読み込み: シングルプレイでは `src/net/`・peerjs・ロビーを読まない（PvP を選んだとき・`?room` のときに別チャンクで読む）

#### PvP の戦闘の決めた数値（5-3。値は `src/data/pvp.ts`、判定は `src/combat/pvp-arena.ts`、表示は `src/net/pvp-mirror.ts`）

- 判定: ホストだけが機銃・ミサイル・フレア・命中・ダメージ・撃墜を決める（シングルと同じ部品と数値: 機銃 15 発/秒・機体ごとのダメージ、ミサイルの範囲ダメージ、フレアの乗り換え）。自分のミサイル・フレアには反応しない。PvP では AI の敵機・的・ドローンは出さない
- 入力: クライアントは 1 ステップごとに fire（押している間）/ missile / flare / targetNext（押したステップ）/ locked（ロック完了中）と選んでいる対象の ID を送る。推測で埋めたステップでは押した瞬間の操作を繰り返さない
- ロックオン: 自機の索敵とロックは各自で計算する（シングルと同じ Targeting。対象は他プレイヤー）。ホストは発射のとき、巻き戻した対象の位置でロックの円錐（角度 + 2°・距離）を見直し、外れていれば無誘導で撃つ
- 遅延補償: ホストは各機の位置を 0.5 秒（30 tick）覚える。クライアントは input に「そのステップで他機を表示していたホストの tick」を入れ、ホストは機銃の当たり判定でその tick の位置へ対象を巻き戻す（RTT 200ms で約 417ms = RTT + 補間 100ms + ホストの入力の溜め 100ms。0.5 秒で頭打ち）。ミサイルは巻き戻さない
- 弾の同期: 機銃の弾は送らない。引き金の変化を fire の event で配り、各自が見た目の弾を出す（当たり判定なし）。ミサイルは state に入れる（最大 16 発、1 発 14 バイト: 位置 0.5m・速度 1/16 m/s）。命中（hit）・起爆（explode）・撃墜（kill）・フレア（flare）・復帰（respawn）・対戦の終わり（over）は event で全員へ
- 帯域: state は 4 機 + 16 発で 379 バイト × 15Hz ≈ 5.7KB/s（6KB/s 以下）。成績（score: 撃墜・被撃墜・機銃の発射数と命中数・残り時間）は撃墜のたびと 1 秒ごと
- HP: state に入る。最大 HP は名簿（welcome）で配る（機体と強化からホストが決める）
- 撃墜と復帰: 撃墜（地面・海面への墜落も）されると 3 秒後に、島を囲む半径 4500m の輪の 8 か所（高度 800m。機首は島の中心なので山頂の約 600m より上）のうち、生きている他機までの最短距離が最も大きい所へ戻る。復帰後 3 秒は無敵（ダメージ 0）で、機体を不透明度 0.4・名札を 0.5 で出す。クライアントは復帰の event の seq より後の自分の操作を出現位置から計算し直す。墜落・撃墜・復帰のカメラはシングルと同じく即スナップ
- ルール: ロビーでホストが撃墜数（10 / 15 / 20）と制限時間（5 / 10 分）を選ぶ。誰かが撃墜数に達するか時間切れで終わり、ロビーの画面にリザルト（順位・撃墜・被撃墜・命中率）を出す。順位は撃墜数 → 被撃墜数の少なさ（同じなら同順位）、命中率は機銃の命中 / 発射。「もう一度」でロビーへ（ホストがもう一度「開始」できる）
- HUD: 他プレイヤーの名札に HP バー（30% 以下は赤）、撃墜のフィード（右上、「○○ が △△ を撃墜」/「○○ が墜落」、4 件・5 秒）、スコアボード（Tab の 0.25 秒の長押し / タッチはレーダーをタップで開閉）、残り時間（上の中央）。レーダーに他プレイヤーを敵機と同じ赤い点で出す
- 音: 他プレイヤーの機銃の発射は敵機の発射音、命中は敵機への命中音、ミサイルの発射・起爆・撃墜の爆発はシングルの音を位置付きで鳴らす
- `?netdebug`: ホストに遅延補償の巻き戻し量（参加者の最大）を足した

#### ロビー・4 人対応・対戦の体裁の決めた数値（5-4。値は `src/data/pvp.ts`・`src/data/net.ts`、ロビーの判定は `src/net/lobby-rules.ts`、ルールは `src/combat/pvp-rules.ts`）

- ロビー（部屋の画面。横に広い画面は 2 列）: 部屋コード・共有 / コピー / QR・ルール（ホストは選ぶ: 撃墜数 10 / 15 / 20・制限時間 5 / 10 分・モード 個人戦 / チーム戦（2 対 2）・「強化を無効にする」（初期 ON）・「初心者保護」（初期 OFF））・参加者（色・名前・機体名・ホスト / あなた・チーム・READY / 準備中 / 再接続中）・定型文 6 種・退出 / ハンガー / 準備OK（クライアント）・開始（ホスト）。横画面のスマホ（高さ 480px 以下）では下のボタンを枠の下端に貼り付ける。すべてタッチで押せる（44px 以上）
- 開始: 2 人以上・ホスト以外の全員が Ready・再接続中の人がいない・（チーム戦は）両チームに 1 人以上で「開始」が押せる。押せない理由を下に出す。対戦が終わると全員の Ready と「もう一度」を外す
- ハンガー（ロビー）: 所持機体だけのダイアログ（速度・旋回・耐久・搭載の倍率）。選ぶと名簿の機体と最大 HP が変わる（セーブの選択機体も）。強化は「強化を無効にする」なら全員 Lv 0、OFF ならシングルの値。飛ぶ機体は名簿の自分の機体
- 共有: 「共有」は Web Share API で OS の共有シート（`URL?room=コード`。`?net=local` だけ残す）、非対応・失敗はリンクをクリップボードへ（「リンクをコピーしました」）。「コピー」はコードだけ。「QR」は参加用 URL の QR コード（自前の生成 `src/core/qr.ts`。誤り訂正 M）を 220px 四方で出すダイアログ。`?room=` で開くと、パイロット名があればロビーへ直行、なければ名前の入力を挟んでロビーへ。読み込んだ後は URL から `?room` を消す
- 定型文: 準備OK / ちょっと待って / もう一戦 / よろしく / ナイス！ / ありがとう。ホストが全員へ配り（同じ人は 1 秒に 1 回まで）、部屋の画面ではその人の行に 3 秒（リザルトの画面では上のお知らせに 3 秒）
- チーム戦: チーム戦に切り替えると ID 順に A・B・A・B に自動で分かれる。ホストはチームの印を押して入れ替え・「チームを自動で分ける」。新しく入った人は少ない方へ。味方には機銃・ミサイル（信管・爆風）が当たらない。撃墜数の上限はチームの合計。名札とレーダーは味方がシアン（名札に ▲）・敵が赤。ロックは敵だけ。残り時間の下に「A 3 − 2 B」。リザルトはチームの合計と勝敗
- 初心者保護: 復帰のとき撃墜数が最下位の人（同じなら全員。全員同じ撃墜数のときは無し）を最大 HP 1.5 倍・ミサイル +2（その命の間）。本人の画面の上に「初心者保護 HP+50%・MSL+2」
- 開始前のカウントダウン 3 秒（3・2・1・GO と音）: 全機を開始位置で止め、操作・射撃は無視、時計も止まる（ホストもクライアントも飛行の始めから数える）
- 残り 30 秒と 10 秒: 画面の上に赤い「残り N 秒」を 2 秒と警告音（上がる 2 音）
- 撃墜されたとき: 「撃墜されました」・撃墜した相手の名前（墜落なら「墜落」）・復帰までのカウント 3 → 1。復帰後 3 秒は画面の上に「無敵 2.4」
- リザルト: 勝利 / 敗北（チーム戦）/ 引き分け / 終了、ベストプレイヤー（最多撃墜。同じなら被撃墜の少ない方 → 命中率）、順位・撃墜・被撃墜・命中率・最長連続撃墜。「もう一度」は押した人に ✓ と「N / 4」、全員そろうとロビーへ（クライアントの「もう一度」は Ready も兼ねる）
- 切断: クライアントが途切れたら（接続が閉じた・6 秒無通信）、ホストは 10 秒その人を「再接続中」で残し（機体は止めて対象外・半透明）、同じ ID と合言葉で戻れば続ける（入力が届き直したら出現位置へ戻す。撃墜に数えない）。10 秒を過ぎたら離脱扱い。クライアントは 10 秒、1 秒ごとにつなぎ直し、その間は自機を止めて「再接続しています…（残り N 秒）」。自分から抜けたときは待たずに消す。ほかの人には「○○ の接続が切れました（再接続を待っています）」「○○ が戻りました」「○○ が離脱しました」。ホストが切断したら従来どおり終了（ホスト移行なし）
- 帯域（4 人・5 分のテストの実測）: ホスト → 各クライアント約 2.6KB/s、各クライアント → ホスト約 1.6KB/s（1 本の接続あたり。ミサイル 16 発でも約 5.9KB/s）
- プロトコルの版 3（設定・名簿・再接続・定型文・最長連続撃墜。state の形は 5-3 のまま）

## 10. ビジュアル

- 目標: 写真のような写実。物理ベースの空（大気散乱。HDR 画像は使わない）、PBR マテリアル、水面（ゲルストナー波）、ブルーム、空気遠近、雲（「中」以上は疑似体積、「低」はビルボード）
- 品質設定: 低 / 中 / 高（自動判定 + 手動）
  - 自動判定: 手動設定 > 自動ダウングレードの保存値（`skyraid.qualityAuto`）> GPU 名がソフトウェアレンダラー（SwiftShader・llvmpipe など）なら「低」、それ以外（タッチ端末を含む）は「中」
  - 自動ダウングレード: 飛行開始から 5 秒間（ポーズ中は数えない）の平均 fps が 30 未満なら一段下げて `skyraid.qualityAuto` に保存し、HUD の上端に 2 秒間「画質を下げました」と出す。飛行開始のたびに測る。手動設定（`skyraid.quality`）があるときは行わない。値は `QUALITY_CONFIG.autoDowngrade`
- マップ: 「海岸と島」と「港湾都市」（6-4。レイド用・フリーフライトと PvP でも選べる。上の「港湾都市と破壊される建物」）。後に「峡谷（レース用）」
- プレースホルダー期間はプリミティブで進め、フェーズ4で差し替え

#### 島・海・空の決めた数値（1-3。値は `src/data/terrain.ts`、画質は `src/data/quality.ts`）

- 島: 8km 四方（原点中心）を 4×4 チャンク（一辺 2km）に分けて描く。外側は海面だけ。シード `20261029` の simplex ノイズで決まり、毎回同じ形
- 形: 中心からの距離を海岸線の半径（平均 2900m、ノイズで ±18%）で割った t（中心 0・海岸 1）で決める。山 `500 × exp(−4t²)` + 平地 `80 × (1 − t)`（海岸でちょうど 0）+ 丘（fBm、振幅 70m）+ 尾根（リッジノイズ、振幅 90m、山の上ほど強い）。最高点は約 600m（実測 609m。4-6 の浸食後は約 597m）。海岸の手前（t 0.7〜1）で丘を消して砂浜をなだらかにする。海岸の外は t 1〜1.35 で海底へ下がり、深さ 60m で平ら
- 色（頂点カラー。4-6 からは画質「低」だけが使う。「中」以上は下の「地形の決めた数値（4-6）」の層）: 海底 → 砂（海面〜4m）→ 草地 → 森（4-6 から木の配置と同じ密度 × 森の層。従来は 90m 付近）→ 岩（400m 付近。従来は 260m）→ 雪（515m 付近。従来は 470m）。境目は ±25m で混ぜる。法線の y が 0.75（約 41°）より急な斜面は岩、雪は急斜面に積もらない。頂点ごとに明るさを ±6% ばらつかせる
- LOD（4-7 で変更）: チャンク（2000m。Mesh 1 つ = draw call 1）を 500m 四方のブロック 4 × 4 に分け、ブロックごとに段を選んでチャンク 1 枚のジオメトリにまとめる。ブロックの分割数 64 / 32 / 16 / 8 / 4（約 8 / 16 / 31 / 63 / 125m 間隔）。カメラからブロックの箱（高さの範囲込み）までの距離が 800m（描画距離に依らない）/ 描画距離 × 0.24 / 0.48 / 0.7 未満でそれぞれの段、描画距離までは最も粗い段、その先は描かない（「中」で 800 / 1200 / 2400 / 3500 / 5000m）。粗くするときだけ 100m 余分に待つ（境目でのちらつき防止）。画質「低」は 16 分割（約 31m）から（4-6 までの「低」と同じ間隔）。ブロックの段・縁の継ぎ合わせが変わったチャンクだけまとめ直す。ブロックの頂点は今と直前の段だけ残す
- 法線（4-7）: 頂点の法線は高さの 3×3 の Sobel（中心差分を隣の列と 1:2:1 で平均）
- LOD の違う隣とのひび割れは、細かい側の縁の頂点を粗い側の直線上に寄せて塞ぐ
- 衝突判定は描画メッシュではなく高さ関数そのもの（`getGroundHeight`）。メッシュは格子の間を直線でつなぐので、低画質では見た目と数 m ずれうる
- 海面は 4-2 で作り直した（下の「海・雲の決めた数値」）。衝突判定は従来どおり「海面 = 高度 0」
- 空・太陽・霧は 4-1 で大気散乱に置き換えた（下の「空・光・ポストエフェクトの決めた数値」）
- 起動位置: (0, 500, 4500)。島の沖合（海岸から約 1.9km）、高度 500m で −Z（島の方向）へ巡航速度。画質「低」の霧（4-1 から 2700m で消える。従来は 2100m）でも海岸が見える距離。そのまま水平に飛ぶと約 16 秒で山の中腹（高度 500m）に当たる

#### 空・光・ポストエフェクトの決めた数値（4-1。値は `src/data/sky.ts`、画質は `src/data/quality.ts`、地形のディテールは `src/data/terrain.ts` の `TERRAIN_DETAIL_CONFIG`）

- 計算は CPU（`src/render/atmosphere-model.ts`、テスト・ライト・露出用）と GPU（`src/render/atmosphere-glsl.ts`）で同じ式。色はすべてリニアの HDR で、最後に ACES でトーンマッピングする
- 太陽: 方位 40°・仰角 32°（午後）。`SKY_CONFIG.sun` を変えるか `Atmosphere.setSun` を呼ぶと、空・ライト・海・露出が計算し直される（7-5 の昼夜用）。大気の外の太陽は 5900K・放射照度 3（平行光源の intensity と同じ単位）。ホワイトバランス 5300K（直射日光が白に近い暖色、地平線の霞が白に写る）
- 大気（Preetham / Hoffman-Preetham 系の単一散乱 + 多重散乱の近似）: Rayleigh 散乱係数 (5.80, 13.56, 33.1)×10⁻⁶/m・スケールハイト 8000m、Mie 1.6×10⁻⁵/m（晴れた日の約 4 倍のうすい霞）・散乱/消散 0.9・スケールハイト 1200m・前方散乱 g 0.76、多重散乱 0.5（等方。空全体から来る光なので太陽の透過率を掛けない）。空気の厚さは Kasten-Young 型の近似（天頂 1・地平線 約 36）
  - 空の明るさ L = E × T_sun × (β_R·P_R + β_M·P_M) / β_ext × (1 − e^−τ) + 多重散乱。T_sun は太陽からの透過率（太陽が低いほど赤い）、τ は視線方向の光学的厚さ。結果として天頂は濃い青、地平線は白く明るく霞み、太陽のまわりは Mie で白く光る
  - 太陽の円盤: 視半径 0.6°（実物の約 2 倍）、明るさは太陽の放射照度 × 40（トーンマッピング後に必ず白く飛ぶ）。画質「中」「低」は太陽のまわりのまぶしさをスカイシェーダーで足す（強さ 0.6・鋭さ 900 と、広いにじみ 0.05・40）。「高」はブルームに任せる
- 空気遠近（霧）: Three.js の霧のシェーダーチャンクを置き換え、全マテリアルに散乱ベースの霧を掛ける（頂点ごとに計算、トーンマッピングの前）。透過率 = exp(−(β_R·ρ_R + β_M,ext·ρ_M) × 距離 × 3)（ρ はカメラと点の高さの間の平均密度。高いところほど薄い）、色 = 同じ向きのスカイの色 × (1 − 透過率)。遠くほど空と同じ色になって溶ける。実際の大気のままだと描画距離（3〜8km）では薄すぎるので、距離を 3 倍にして計算する。4-2b: この倍率はカメラの高さで exp(−高さ / 1960m) 倍に減らす（1000m で地上の 60%、2000m で 36%。地表付近の見え方は 3 倍のまま、上空では霞が薄くなり見下ろした地形・海のコントラストが残る。`SKY_CONFIG.aerial.heightFalloff`）。描画距離の果ては描画距離 × 0.55〜0.9 で背景の色に溶かしきる（地形・海の切れ目を隠す。`QUALITY_CONFIG.fogNearRatio` / `fogFarRatio`）。背景は地平線より上は空、下は「描画距離の外の海面（濃紺の水 + 空の反射）を空気遠近ごしに見た色」（4-2b。スカイドームの地平線より下も同じ色。以前は地平線の霞の色だったため、上空から見下ろすと描画距離の果てが白く溶けて画面全体が白くなった）。4-7: カメラの高さ 500m 以下は倍率をさらに 0.8 倍（500〜700m でなめらかに 1 倍へ戻す。700m より上は 4-2b のまま。`SKY_CONFIG.aerial.lowFactor` / `lowFrom` / `lowTo`。地表で距離 2.4 倍）
- 霧の uniform の読み替え: `fogColor` = 太陽の向き × 放射照度、`fogNear` / `fogFar` = 描画距離の果てのフェード。画質「低」（画面に直接描く）では Three.js が `fogColor` を sRGB に変換して渡すので、逆変換した値を入れておく
- ライト: 平行光源 = 地上に届く太陽光（大気の外の光 × 透過率。午後 32° でリニア約 (2.27, 2.36, 2.01)）。半球ライト = 空全体から水平面に届く放射照度（スカイを 12×24 で数値積分）と、地面の照り返し（反射率 0.1）
- 露出: 地面（反射率 0.15 の拡散面）と空の明るさの対数平均（地面の重み 0.6）が 0.15 になる倍率。ただし露出後の地面が 0.14 より暗くならないよう下限をかける（空が明るくても地形がつぶれない）。午後 32° で約 2.2。トーンマッピングは ACES（全画質）
- 影（画質「中」以上）: 太陽光のシャドウマップ。範囲は機体を中心に 600m 四方（タイトル画面はカメラのまわり）、解像度は「中」1024・「高」2048、光の向きに垂直な面で画素単位に丸めて追従させる（ちらつき防止）。影を落とすのは自機・敵機・ドローン・風船、受けるのは地形と自機。地形自身は影を落とさない（範囲が狭く、山の影が範囲の端で切れるため）。海はシャドウマップの影を受けない（4-2 の雲の影だけ）
- ポストエフェクト（画質「中」以上、three/examples/jsm の EffectComposer）: シーン（HalfFloat・MSAA 4x）→ ブルーム（「高」のみ。UnrealBloomPass、強さ 0.35・半径 0.4・しきい値は露出後の輝度 2.2）→ 仕上げ 1 パス（ビネット 四隅で 22% 暗く + 露出 + ACES + sRGB）。「低」はポストエフェクトなしで、ACES はレンダラー側（各マテリアルの最後）
- 地形のマテリアル: 「中」以上は PBR（`MeshStandardMaterial`、粗さ 0.95）+ 三面マッピングの手続きノイズ（テクスチャ画像なし）で頂点カラーの明るさをばらつかせる。細かい粒（一辺 1.5m・±25%・120〜380m で消える）、まだら（8m・±20%・500〜1400m）、大きな色むら（60m・真上から投影・草地は黄緑 ⇄ 深緑）。急斜面（法線の y 0.85→0.65）は岩として粒を 1.6 倍。「低」は従来どおり Lambert（頂点カラーだけ）
- マテリアル: 機体・的・ドローン・ミサイル・煙・破片は `MeshStandardMaterial`。発光する演出（曳光弾・火花・マズルフラッシュ・フレア・爆発の閃光）は基本色が黒の `MeshStandardMaterial` + emissive で、明るさは露出後の値で指定（曳光弾 1.1・火花 1.3 は色が分かるようブルームのしきい値の下、マズルフラッシュ 5・フレア 6・爆発 5 はブルームで光る）。霧は掛けない
- 品質フラグ（`QualityPreset`）: 低 = 影なし・ポストエフェクトなし・ブルームなし・地形ディテールなし / 中 = 影（1024）・ポストエフェクト・地形ディテール、ブルームなし / 高 = すべて（影 2048）
- デバッグ表示（F3）に「steps」（1 フレームの描画ステップ数: シャドウマップ + シーン + ポストエフェクトのパス。ブルームは内部 13 回）を足した。draw calls はポストエフェクトのパスを含めた 1 フレームの合計

#### 海・雲の決めた数値（4-2。海は `src/data/ocean.ts`、雲は `src/data/clouds.ts`、風は `src/data/wind.ts`、画質は `src/data/quality.ts`）

- 風: 向き 30°（+X から +Z へ。島の南西から北東）。海の波・さざ波・泡の流れ・雲の流れ（9 m/s）はすべてこの向きを基準にする。`WIND_CONFIG.direction` を 1 つ変えると全部が揃って回る
- 海面（画質「中」以上）
  - 波: ゲルストナー波 6 本。うねり 2 本（風向き −20° / +35°、波長 220 / 140m、振幅 0.5 / 0.35m、鋭さ 0.1）+ 風波 4 本（0° / +25° / −30° / +50°、波長 42 / 27 / 17 / 11m、振幅 0.22 / 0.15 / 0.1 / 0.06m、鋭さ 0.22 / 0.18 / 0.16 / 0.14）。振幅の合計 1.38m（上限 1.5m。船酔い防止）、鋭さの合計 0.9（< 1 で波の頂点が輪にならない）。速さは深海の分散関係 ω = √(g·k)（うねり 18.5 m/s・周期 11.9 秒、いちばん短い風波 4.1 m/s・2.7 秒）。計算は `src/render/gerstner.ts`（CPU、テスト用）と頂点シェーダーで同じ式。見た目だけで、衝突判定は「海面 = 高度 0」のまま
  - 浅瀬では波を小さくする（水深 0.3m で 0、8m で元の振幅）。波打ち際で海面が砂浜にかぶらない
  - メッシュ: カメラ中心の同心リング（角度 160 分割、半径 2m から描画距離 × 1.1 まで等比。隣の輪との間隔 ≒ 円周方向の間隔で、距離 d での頂点の間隔は約 d × 0.039）。「中」約 3.3 万頂点（三角形 約 6.6 万）、「高」約 3.5 万頂点（約 7 万）。4-1 の平面（64 分割、約 0.4 万頂点）から増えた分は頂点シェーダーだけで、画質「中」のスマホでも負担は小さい見込み。頂点の間隔が波長の 1/8 を超えた波から消し始め、1/4 で消しきる（遠くのちらつき防止）
  - さざ波: 頂点は動かさず、フラグメントで 2D 勾配ノイズ（値と微分を同時に出す。テクスチャ画像なし）から法線を作る。層 1（模様 9m・風向きに 1.2 m/s・傾き 0.32・250〜1600m で消える）、層 2（2.6m・+70° に 0.6 m/s・0.22・80〜450m）、層 3（0.8m・−45° に 0.3 m/s・0.14・30〜140m）。「中」は 2 層、「高」は 3 層（`QualityPreset.oceanLayers`）
  - 色: 水の色（反射率）は水深で混ぜる（浅瀬のターコイズ #2fb8b0 → 沖の濃紺 #0a2c4a、exp(−水深 / 6m)）。照らす光は地形と同じ太陽 + 空の放射照度 / π。空の反射は Schlick のフレネル（F0 0.02）× 0.9 で、空の色はスカイと同じ大気散乱の式（4-1）
  - 遠くの空の反射（3-1 の事前修正）: 遠くでは視線が海面にほぼ平行で、水平線すぐ上の白い空を映して空と見分けがつかなかった。実際の海では遠くほど手前を向いた波の斜面ばかりが見えるので、反射の向きの上向き成分にカメラからの距離 800m で 0 → 4000m で 0.12（約 7°）を smoothstep で足し、少し上の青い空を映す（800m 未満は変えない。画質「低」の頂点計算も同じ）。描画距離の外の海面（スカイドームの地平線より下・描画距離の果ての背景）も同じ 0.12 を足す。水平線で海と空の境目が見える（`OCEAN_CONFIG.horizonReflection`）
  - 太陽の照り返し: GGX（Schlick のフレネル、Kelemen の可視項）。粗さ α は近く 0.07、さざ波が弱まった・消えた遠くでは 0.2（細かい波を粗さとして扱い、照り返しが沖まで帯状に広がる）
  - 4-2b: さざ波の傾きを距離で 1 / (1 + (距離 / 500m)^1.6) 倍に弱める（500m で 50%、2000m で約 10%）。粗さ α もこの割合で近く → 遠くの値へ移す。1 画素が海面で覆う幅（画面の微分）が模様の大きさ × 0.15 を超えた層は消し始め、× 0.4 で消しきる（画素より細かい法線を使わない）。照り返しの強さは 1 → 0.6。波のない海面（ゲルストナー波の法線）で太陽を映す向きから 7° 以内を帯とし、20° まで弱め、帯の外は 0.12 倍・露出前の輝度 0.35 で頭打ち（露出の上限 3 でもブルームのしきい値 2.2 未満。「低」の簡易版も同じ帯を使う）
  - 水面下の散乱っぽい明るさ: 太陽の方を見たとき、波の山ほど緑がかったターコイズ（#2aa58f、強さ 0.6）が透けて明るくなる
  - 海岸の泡: 地形の高さ関数から起動時に水深の格子（8km 四方を 384×384、約 21m 間隔。HalfFloat のテクスチャ、線形補間。約 60ms）を作り、「水深 ÷ 水深の勾配」で海岸線までの距離を見積もる。距離 26m 以内（水深 3m 以内）に白い帯（反射率 0.8）。帯の端は 7 秒周期で ±35% 寄せては返し、ノイズ（3.5m）でちぎって風下へ流す。遠浅でも急でも帯の幅が揃う
  - 「高」: 画面空間の反射は入れず、空の反射を 1.08 倍・太陽の照り返しを 1.3 倍に（`QualityPreset.oceanBoost`）。雲の影も受ける
- 海面（画質「低」）: 4-1 の簡易版（カメラ追従の平面、64 分割、頂点の波はうねり 1 本を正弦波で、水の色と空の色は頂点で計算）に、さざ波の層 1 だけをフラグメントで足してフレネルと照り返しを揺らす。頂点数は変えない。水の色は「中」以上の沖と同じ濃紺
- 雲（画質「中」以上）: 高度 1500〜2200m の層。カメラに追従する板（層の下面と上面の 2 枚、1 メッシュ）を描き、画素ごとに視線と層の交わる区間を一定の歩数で進む疑似体積（「中」8 歩・「高」12 歩。上限はシェーダーの定数 12、`QualityPreset.cloudSteps`）。1 本の視線で進むのは最大 1500m。カメラが層の下なら下面だけ、上なら上面だけ、中なら両方を描く
  - 密度: 起動時に作るタイル状の 3D ノイズ（32³、Worley と値ノイズの fBm を 6:4。約 70ms）を 3D テクスチャにして、形（4200m で 1 周）・縁を削る細部（640m）・被覆率を場所ごとに ±0.15 揺らす大きな模様（23km）の 3 回読む。高さの重みは底で平ら（下から 10% で最大）・上は丸く細る（積雲）。形 × 重みの上位「被覆率」だけを雲にする（被覆率 0.45。上げるほど密度が増える）。消散係数 0.03/m
  - 光: 太陽の方へ 140m 先の密度を 1 回取って自分の影にし、さらに下ほど暗く（底は 45%）。位相関数は Henyey-Greenstein の前方（g 0.6）と後方（−0.15）を 6:4 で混ぜる（太陽の方を見ると縁が光る）。空の光は上ほど明るい（底 0.45）。結果、下から見ると底が灰色で縁が明るく、上から見ると白い綿
  - 歩く位置は各歩の中央（画素ごとにずらさない）。層の外から入る視線は全画素が同じ高さの組で取るので縞にならず、ずらすと 8 歩では砂のようなざらつきになったため
  - 遠くの雲は地形・海と同じ空気遠近の式で空の色に溶け、描画距離 × 0.55〜0.9 で消える
  - 4-2b: 板はカメラの位置に付いて動くが向きは常に世界の水平。視線は画素の NDC からカメラの投影の逆行列とワールド行列で世界座標の向きを求める（ロール・背面飛行でも雲が地平線と同じだけ傾く）
  - 風で 9 m/s で流れる（ポーズ中は止まる）
- 雲（画質「低」）: ビルボード 40 枚（InstancedMesh、draw call 1）。カメラのまわり 2600m 四方に置いて回り込ませ（端の 30% で薄くする）、世界の上方向を軸にカメラへ向ける（右は常に水平でカメラのロールに追従しない。上下はカメラの方へ傾けて、層の上・真下から見ても線にならない。4-2b）。形はノイズの輪郭（平らな底）、色は空の光（太陽 + 空。上ほど明るく底は暗い）。幅 450〜1100m、高さは幅 × 0.45、高度 1600〜1950m
- 雲の中の霧: カメラが層の中にいると、画面全体に薄い白（層の中にいるだけで 22%、カメラの位置の雲の密度で最大 60%。層の端 60m でぼかし、濃さは 1/4 秒で追従）を重ねる。カメラの位置の密度は GPU と同じ式・同じノイズを CPU で読む。疑似体積は層の中では水平に近い視線ほど薄くする（板に当たらない向きとの境目を隠す）
- 雲の影（画質「高」のみ。`QualityPreset.cloudShadows`）: シャドウマップではなく、地形・海の点から太陽の方へ層の 30% の高さまで伸ばした点の密度（細部なし）で直射光を最大 55% 暗くする。地形は直射光だけ、海は照り返しと水の中の光の太陽の分だけ暗くなる
- draw call: 海 1 + 雲 1（疑似体積かビルボード）+ 雲の中の霧 1（層の中にいるときだけ）= 最大 3（4-1 から +2。海は従来も 1）
- 品質フラグ（4-2 で追加）: 雲の方式 `cloudMode`（低 billboard / 中・高 volume）、雲の歩数 `cloudSteps`（— / 8 / 12）、海の層数 `oceanLayers`（1 / 2 / 3）、反射の強化 `oceanBoost`（高のみ）、雲の影 `cloudShadows`（高のみ）

#### 地形の決めた数値（4-6。地形は `src/data/terrain.ts` の `TERRAIN_CONFIG.shape.coast` / `TERRAIN_CONFIG.erosion` / `TERRAIN_DETAIL_CONFIG`、木は `src/data/vegetation.ts`、画質は `src/data/quality.ts`）

- 方向性: 写真のような写実。テクスチャ画像・Web フォントは使わず、すべて手続き生成
- 浸食（`src/render/terrain-gen/erosion.ts`、Three.js 非依存）: 起動時に 1 回、粒子ベースの水力浸食。島を覆う 7400m 四方を 256×256（約 29m 間隔）の格子にし、雨粒 28000 粒（シード固定）を陸の格子点に落とす。雨粒は最急勾配へ慣性 0.05 で 1 マスずつ最大 30 歩進み、運べる量（下り坂の勾配 × 速さ × 水量 × 8、最低 0.01）に余裕があれば 40% 削り（3×3 の筆で周りに配る）、超えたら 30% 落とす。水は 1 歩で 2% 蒸発。海に着いた雨粒は運んでいた土ごと消える。結果、尾根が鋭くなり、谷に溝ができ、山裾に扇状の堆積が出る
  - 浸食の前後の差分を Catmull-Rom で補間して高さ関数に足す（細部は従来のノイズのまま）。`getHeight` がその値を返すので、衝突・リング配置・AI の地形回避・描画メッシュ・水深の格子はすべて同じ高さを使う
  - 浸食前の高さが海抜 5m 以上の所にだけ効かせ（5〜20m で 0 → 1）、削っても 5m より下にはしない。海岸線・浅瀬・水深の格子（4-2c）は浸食の前と同じ

- 海岸の作り分け: 中心から見た向きと風向き（`WIND_CONFIG.direction` 30°）の内積をノイズ（±0.3）で揺らし、−0.15〜0.55 で風上 / 風下らしさ 0 → 1
  - 外洋側（風上。南西）: 内陸から緩く上がった台地（海岸から約 200m で 32m）が、海岸の約 35m の幅で崖になって海へ落ちる。崖の下の海底の棚は 45% まで狭い（すぐ深い）。崖は浸食の後で足す（格子より細いので浸食で崩さない）
  - 風下（北東）: 海岸の手前（t 0.8〜1）を最大 55% 低くして遠浅の浜を広げる。浸食の堆積は風下で 1.6 倍、風上で 0.4 倍
  - どちらも t = 1（海岸線）の高さ 0 は変えないので、海岸線の平均半径は浸食・作り分けの前と同じ（テストで ±5% 以内を確かめる）
- 質感の層（画質「中」以上。地形のシェーダーの中で決める。`src/render/terrain-layers-glsl.ts`）: 海底 → 砂浜（上端は風上 2.5m・風下 8m）→ 草地 → 森（木と同じ密度 × 高度 20〜350m × 傾斜 25° 以下。暗い緑のまだら）→ 高原（340m〜。草と岩屑）→ 岩（400m〜、または傾斜 30° 以上）→ 崖（傾斜 50° 以上。高さ 4.5m 間隔の地層の縞をノイズでうねらせる）→ 雪（515m〜。北向き（+Z。太陽の反対側）の斜面ほど最大 80m 低くまで、南向きは 24m 高く。傾斜 45° より急な所には積もらない）
  - 境目: 大小 2 枚のノイズ（37m / 9m）で高さの境目を ±14m、傾斜の境目を ±5° ずらす（直線にならない）
  - 粒: 三面マッピングの値ノイズ 3 枚（細 0.8m・粗 3.5m・まだら 14m。それぞれ 100〜300m / 250〜800m / 700〜2000m で消える）を層ごとの強さで混ぜる。草は細かい粒が強く（±28%）、岩は粗い粒が強い（±35%）。大きな色むら（60m、草地の黄緑 ⇄ 深緑）は 4-1 のまま
  - 法線の細部（`QualityPreset.terrainNormalDetail`。「中」「高」）: 岩・崖の面を、三面マッピングのノイズの勾配（4.5m・深さ ±1.2m と 1.3m・±0.25m）と崖の縞の段差（0.25m）で揺らす。250〜900m で消える

- 木（`src/render/vegetation.ts`、配置は `src/render/terrain-gen/forest.ts`）: 森の層（高度 20〜350m・傾斜 25° 以下。傾斜は高さ関数の 6m の前進差分）に、森の密度（値ノイズ 420m と 95m を 0.65 : 0.35 で混ぜ、0.38〜0.62 で 0 → 1）に比例して決定的に撒く。本数は 低 3000 / 中 12000 / 高 30000（`QualityPreset.treeCount`）。少ない本数は多い本数の先頭と同じ並び
  - 近く（600m 以内）: 1 つの InstancedMesh の針葉樹（円錐 2 段 + 円柱、約 40 三角形、葉は下ほど暗い）。高さ 11〜23m、幅は高さの 0.64〜0.9 倍、明るさ ±18%。風（`WIND_CONFIG.direction`）の向きに梢が最大約 0.35m、1.4 rad/s で揺れる。カメラが 50m 動くごとに 650m 以内の木を詰め直す
  - 遠く: 全部の木の十字ビルボード（カメラを向く縦の板 + 樹冠の高さの水平の板）を 1 つのジオメトリで。輪郭はフラグメントで捨てる（縦は縁がぎざぎざの三角形と幹、水平は縁が波打つ円）。色は 4-1 の空気遠近で距離とともに空に溶ける
  - 根元は 1.5m 沈める（地形の LOD の直線補間で浮かないように）。影は落とさず受けず、衝突判定もしない
  - 木の影の代わり（「高」のみ、`QualityPreset.treeShade`）: 地形のシェーダーで、地面の点から太陽の方へ木の高さ × 0.8 ずらした点の森の密度 × まだら（5m）で直射光を最大 50% 暗くする。1500〜2500m で消える
- 品質フラグ（4-6 で追加）: 木の本数 `treeCount`（3000 / 12000 / 30000）、法線の細部 `terrainNormalDetail`（— / あり / あり）、木の影の代わり `treeShade`（高のみ）

#### 音（4-4。数値は `src/data/audio.ts`、仕組みは `src/audio/`。Web Audio API の合成だけで、音声ファイルは BGM の受け口だけ）

- 基盤: AudioContext は最初のユーザー操作（pointerdown / touchend / keydown / click）で作り、resume して無音を 1 回鳴らす（iOS Safari の制限）。中断されたら次の操作で resume。マスター / 効果音 / BGM の 3 本のゲイン。ポーズ中はミュートせずマスターを 30%。タブが裏に回ったら suspend、戻ったら resume。iOS のサイレントスイッチ（消音モード）では鳴らない（仕様。README）
- リミッター（4-11）: 効果音のバスの末尾（効果音のゲイン → リミッター → 補正のゲイン → マスター）に DynamicsCompressor（しきい値 -3dB・比 20・アタック 2ms・リリース 80ms・knee 0）。Web Audio のコンプが自動で足すメイクアップゲイン（+1.71dB）を後ろのゲイン（0.821 倍）で打ち消すので、-3dB より小さい音は素通し。Chromium の実測で -20 / -10.5 / -6 / -3.1dB の入力は同じ値で出て、0 / +6 / +12dB の入力は -2.63 / -2.16 / -1.74dBFS（立ち上がりも 0dBFS を超えない）。BGM のバスには入れない
- 同時発音 16: 常時鳴る 4（エンジン・風切り・ロックオン・警告）+ 単発 12。単発はボイス（フィルタ → 音量 →（パンナー →）効果音のバス）をプールで使い回し、足りなければ一番早く終わるものを止めて使う。ノイズのバッファ（2 秒）は全部で共有
- エンジン: 鋸波（スロットル 0 → 1 で 42 → 88Hz を対数で、音量 0.05 → 0.1、ローパス 380Hz）+ ノイズ（ローパス 320 → 1200Hz、音量 0.07 → 0.15）。アフターバーナーでハイパス 2400Hz のノイズ（0.11）を足し、鋸波を 1.15 倍。撃墜中・メニューでは消す
- 風切り: バンドパスのノイズ。速度 80 → 460 m/s で 260 → 3000Hz（対数）、音量 0.015 → 0.16、Q 0.8。失速（度合い 1）で周波数 0.45 倍・Q 5・音量 +0.05（こもって揺れる）
- 機銃: ローパス 3200Hz のノイズ 0.07 秒 + サイン波のクリック（140 → 45Hz）+ 重さの低域パルス（4-12。サイン波 120 → 80Hz・0.05 秒・ローパス 400Hz）。1 発ごとに重ね、1 描画フレームで最大 2 発ぶん。敵機の機銃は位置つきで音量半分、全機まとめて 0.09 秒より詰めない
- ミサイル発射（4-12 で 3 層に。それまではノイズのローパスを 5200 → 260Hz へ 1.2 秒で下げるだけ）: 1.6 秒
  - 点火のクラック: ハイパス 1500Hz のノイズ 30ms
  - 低域のうなり: 鋸波 80 → 50Hz（ローパス 220Hz）が 0.8 秒で減衰
  - 離れていくシュー: ノイズのローパスを 6000 → 300Hz へ閉じながら 1.6 秒
  - ドップラー: うなりとシューの周波数に 音速 343 / (343 + 遠ざかる速さ) を掛ける（遠ざかる速さはミサイルの推力 220 m/s² で増え、最高速 700 − 巡航 250 = 450 m/s で頭打ち。0.8 秒で 0.66 倍、1.6 秒で 0.49 倍）。8 区間の折れ線（指数ランプ）
  - 自機は定位なし、敵機は位置つき
- 機銃の命中音（4-12。自機の弾が対象に当たったとき。定位なしの手応え）: 金属の衝撃（三角波 230・310・385Hz + 300Hz・Q 14 のバンドパスのノイズが 0.12 秒で減衰）+ 高域のクラック（ハイパス 3500Hz のノイズ 18ms）+ 低域のドン（サイン波 90 → 60Hz・40ms）。1 描画フレームに何発当たっても 1 回、0.03 秒より詰めない。連続ヒットはソフトのコンプ: 直近のヒットの量 n（1 発ごとに +1、時定数 0.25 秒で減る）で音量を 1 / √(1 + n)（15 発/秒で当て続けると約 0.45 倍で落ち着き、音の重なりを足しても 1 発目と同じくらい）
- 撃墜（4-12。自機が敵側を落としたとき。爆発の音に重ねる、定位なし）: 金属が裂ける音 = バンドパス（Q 6）のノイズを 2600 → 700Hz へ下げ、37Hz の矩形波で音量を刻む + 鋸波 520・733Hz（不協和）を 0.35 秒で半分の高さへ。0.45 秒
- 爆発（規模ごと。低域のインパルス = サイン波の下降 + ローパスのノイズの減衰）: small 120 → 50Hz・2600Hz・0.6 秒 / 機体 95 → 38Hz・1900Hz・1.2 秒 / 地上目標 80 → 32Hz・1500Hz・1.8 秒 / 燃料タンク 65 → 26Hz・1100Hz・2.8 秒。海面への墜落は small の音
- ロックオン: 進行中は 1000Hz のサイン波を 2Hz で（周期の 45%）、完了で 1500Hz の連続音
- 警告: 矩形波のビープ。MISSILE 1250Hz・6Hz / PULL UP 620Hz・3Hz / AAA 880Hz・4Hz / STALL 420Hz・2.5Hz。同時なら この順で 1 つだけ。条件は HUD と同じ（PULL UP は地表から 100m 未満、STALL は失速 > 0）
- 被弾（自機）: 矩形波のクリック（2300 → 900Hz・0.04 秒）+ ハイパスのノイズ 0.09 秒
- 対空砲（位置つき）: 砲声（160 → 60Hz・0.18 秒）とフラックの破裂（110 → 45Hz・0.48 秒）
- UI: ボタンを押すとタップ音（1900Hz・0.035 秒）、決定・出撃（`.is-primary`）は決定音（880・1320Hz の 2 音）、ハンガーの購入・強化は和音（C・E・G・C を 0.04 秒ずつずらす）
- 3D 配置: 敵機・爆発・対空砲は PannerNode（equalpower・inverse・基準 120m・最大 10000m）。リスナーはカメラ。6000m より遠い音は鳴らさない。自機・UI の音は定位なし
- BGM: `public/audio/bgm/` の `title.mp3`（タイトル〜ハンガー）・`flight.mp3`（飛行・ポーズ）・`result.mp3`（リザルト）があればループ再生し、画面が変わると 1 秒でクロスフェード。無ければ無音（Content-Type が `audio/*` でデコードできたものだけ使う）。差し替え方は README
- 設定: ポーズメニューの設定に「マスター / 効果音 / BGM」の 3 本のスライダー（0〜100。初期値 80 / 80 / 60）。動かしている間は音に反映し、離したらセーブの `settings.volume` に保存

#### 天候と時間帯の決めた数値（7-5。値は `src/data/weather.ts`、補間と時間の進行は `src/core/weather-state.ts`（Three.js 非依存）、光の計算は `src/render/atmosphere-weather.ts`、描画は `src/render/weather/`、画面とのつなぎは `src/ui/weather-link.ts`。決定は `docs/decisions.md` の 7-5）

- 方向性: 写実。4-1 の大気散乱・4-2 の雲と海を、太陽の位置と天候の値で動かす。画像アセットは使わない
- 時間帯（太陽の仰角）: 早朝 8°（橙〜桃）/ 昼 32°（4-1 のまま）/ 夕方 12°（赤橙）/ 夜 −10°（月光と星）。太陽の通り道は仰角 = 55° × sin(2π(時 − 6) / 24)、方位 = 40° +（時 − 15.63）× 15°/時（昼 32° の午後が 4-1 の方位 40°）。プリセットの時刻は仰角から逆算（早朝 6.56 時・方位 −96°、夕方 17.16 時・方位 63°、夜 18.70 時）
- 低い太陽の色（`SUN_TINT`）: 太陽光の色に、仰角 6° 以下で最大・26° で 0 になる暖色を掛ける（朝 (1, 0.72, 0.7)・夕 (1, 0.6, 0.34)、仰角 6° 以下で最大、輝度 1 に正規化）。地平線の下は 0 → −6° で消す。昼 32° は 4-1 と同じ
- 天候: 快晴（被覆 0.45 = 4-2 のまま）/ 曇り（被覆 0.85、空を曇天の灰色へ 0.8 混ぜ、直射光を 0.8 × 0.9 = 72% 遮る、空気遠近 ×1.3、露出 −0.25EV）/ 霧（視程 1.5km = 消散係数 3.0 / 1500m（気象光学距離。海面、スケールハイト 600m。7-A の事前修正で 1500m から下げ、上空 500m 以上から島の輪郭が見える）、空気遠近 ×2.5、灰色 0.75、被覆 0.6）/ 雨（被覆 0.95、雲の明るさ −33%、灰色 1、視程 4km、空気遠近 ×2、露出 −0.45EV、雨の粒・海の波紋）
- 曇天の空: CIE の曇天（天頂の明るさ Lz × (1 + 2 sin 仰角) / 3）。Lz は「晴れの空の放射照度 + 遮った直射光 × 0.45」を輝度で灰色（わずかに青い (0.96, 1, 1.06)）にした放射照度 × 9 / 7π。雲の層の上（カメラの高さ 1700 → 2500m）では晴れの空に戻す
- 風: 弱（4-2 のまま）/ 強（雲の流れ ×2.5 = 22.5 m/s、風波の振幅 ×1.2・鋭さ ×1.1（振幅の合計 1.49m・鋭さ 0.97）、さざ波の傾き ×1.35、木の梢の振れ ×2.2・速さ ×1.6）。飛行モデルには影響させない。速さを変えても雲・木の位置が飛ばないよう、前回からの時間 × 今の速さで進める
- プリセット 8 種: 昼・快晴・弱風（初期値）/ 早朝・快晴・弱風 / 夕方・快晴・弱風 / 夜・快晴・弱風 / 昼・曇り・強風 / 早朝・霧・弱風 / 昼・雨・強風 / 夜・雨・強風
- 夜: 太陽の明るさは仰角 1° → −9° で 0 に、月（方位 −28°・仰角 24°、起動位置から左前）は夜らしさ（仰角 2° → −8° で 0 → 1）で出す。月の明るさは太陽 3 に対して 0.42、色は青白い (0.55, 0.78, 1.2)（輝度 1 に正規化）。空はシェーダーで太陽と月の両方を計算して足す（時間が流れて地平線をまたいでも途切れない）。直射光（平行光源・影・海の照り返し・雲の光）は地上で明るい方の向き（入れ替わるのはどちらも暗い夕暮れ）
- 月: スカイドームに円盤（視半径 0.9°、明るさ = 月の放射照度 × 260、海の模様の濃淡と周縁減光）と周囲の光（強さ 0.5・鋭さ 400）。曇天・霧では太陽と同じく隠れる（(1 − 0.97 × 曇天) × exp(−霧 × 2500)）
- 星: 手続き生成の点（Points 1 draw call、シード固定、暗い星ほど多い明るさの分布、青白〜橙）。「低」1000・「中」2500・「高」4000 点（`QualityPreset.starCount`。少ない数は多い数の先頭）。描画距離 × 0.9 の天球に置き、地平線の近くは消す。明るさ = 夜らしさ ×（1 − 曇天）× exp(−霧 × 3000) ×（1 − 雨）。0 なら描かない（昼は draw call を増やさない）
- 露出: 昼は 4-1 の自動露出（上限 3.0 のまま）、夜は固定露出 2.2（曇り・雨は ×(1 + 0.35 × 曇天) で最大 2.97）。夜らしさで混ぜ、天候の補正（EV）は昼の分だけ掛ける（上限 3.0）。夕方の自動露出が上がりすぎる問題は上限 3.0 で止まる
- 共有 uniform: 霧のシェーダーチャンクを使う全マテリアル（標準のマテリアル・海・雲）に `uAtmoWeather`（空気遠近の倍率 − 1・霧・曇天）・`uAtmoMoon`（月の向きと明るさ）・`uAtmoGrey`（曇天の空）・`uAtmoSunTint`（低い太陽の色）を入れる。値のオブジェクトを共有するので書き換えると全部に効き、入っていないマテリアルでは 0（= 4-1 の晴れの昼）
- 環境マップ（機体・木）: 天候・時刻が変わったら焼き直す（補間中・時間の進行中は 1 秒に 1 回まで、止まったら最後に 1 回）
- 遷移: プリセットが変わると 3 秒で補間（smoothstep）。時刻は 24 時間の輪の近い方を回る（太陽が通り道に沿って動く）。補間するのは太陽の位置・曇天・被覆・雲の暗さ・霧・空気遠近・雨・風・視認性・露出の補正
- 時間の進行: フリーフライトだけ「時間が流れる」を ON にできる（1 ゲーム日 = 10 実分。ポーズ中は止まる）。ミッション・PvP・レイドは固定
- 各モード: フリーフライトはマップの選択の画面で天候と「時間が流れる」（初期は昼・快晴・OFF）。キャンペーンは M1 昼・快晴 / M2 早朝・快晴 / M3 昼・曇り・強風 / M4 夕方・快晴 / M5 夜・雨・強風（ブリーフィングに「天候」）。PvP・協力レイドはロビーのホスト設定（`GameSettings.weather`、welcome で全員に配る。プロトコルの版 6。初期値は PvP 昼・快晴、協力レイド夕方・快晴）。ソロのレイドは夕方・快晴。メニューの背景は昼・快晴、ブリーフィングとロビーはその天候を下見する
- 雨（画質「中」以上）: 線の粒（InstancedMesh 1 draw call、「中」3000・「高」6000 本）。カメラのまわり 90 × 60 × 90m の箱にワールド固定で回り込ませ、カメラに対する相対速度 × 0.025 秒（0.5〜7m）の筋にする（速く飛ぶほど長い）。落ちる速さ 9 m/s、風で 2.4〜6 m/s 流れる。幅 12mm（遠くは距離 × 1.6mm）、不透明度 0.32、45m で消える。色は空の光で照らした水。雲の層の上（1500 → 1750m）では降らない
- 雨（画質「低」）: 全画面の半透明の筋 1 枚（70 列、不透明度 0.13、画面の歪みなし）。筋の向きはカメラに対する粒の相対速度を画面に写した向き（ロールしても雨は世界の下へ落ちる）
- 海の雨の波紋（画質「中」以上）: 1.3m の格子ごとに 1 つ、0.9 秒周期で中心を変えて広がる輪を 2 層ずらして重ね、法線の傾き（0.35）にする。1 画素が覆う幅が格子の 12〜35% で消す
- HUD: 霧・雨・夜（視認性の悪さ = max(天候の値, 夜らしさ)）は敵のマーカー（四角・選択の枠・予測照準点）を索敵距離（5000m）の 60% = 3000m より遠いと出さない。画面外の選択対象の矢印とレーダーは出す。索敵・ロックはそのまま。夜は HUD の不透明度を最大 0.72 倍（ポーズメニューの設定「夜の HUD 減光」で OFF にできる。セーブの設定 `nightHudDim`、版は上げない）
- 音: 雨はバンドパス（1500Hz・Q 0.6）のノイズ、音量 0.045 × 雨の強さ（機内なので小さく）。強風は風切り音 ×1.6、突風のゆっくりした揺れ（0.13Hz・深さ 30%）。夜は環境音（風切り・雨）を 0.7 倍
- 開発用: `?weather=<プリセット id>` でフリーフライトの天候（`?skipTitle` と一緒なら補間なし）、`?timeflow` で「時間が流れる」を ON

#### フォトモードの決めた数値（7-A。値は `src/data/photo.ts`、軌道カメラ・画面の調整・天候の上書き・解像度は `src/core/photo-*.ts`（Three.js 非依存）、描画は `src/render/photo/`・`src/render/post-grade.ts`・`src/render/focus-pass.ts`、UI は `src/ui/photo/`。決定は `docs/decisions.md` の 7-A）

- 入り方: ポーズメニューの「フォトモード」、またはキーボード P（飛行中・ポーズ中。もう一度 P で出る）。フリーフライト・キャンペーン・ソロのレイドだけ（PvP・協力・チュートリアルではボタンを出さず P も効かない）。画面の状態 `photo`（飛行・ポーズ → photo → 飛行）。固定ステップは止める（時間停止）
- 自由カメラ: 機体中心の軌道。角度は機首の向きの水平の枠（バンクしても地平線は水平）。1 本指 / 左ドラッグで回転（1px 0.3°）、ピンチ / ホイールでズーム（1 ノッチ ×1.12）、2 本指 / 右ドラッグで平行移動（画面の高さ 1 つ分 = 距離 ×1）。距離 4〜300m、注視点のずらし 120m まで、平行移動を足してもカメラは機体から 300m 以内（向きを保って近づける）。仰角 ±85°、地面・海面から 2m 以上。入ったときは後方 12° 上・28m・画角 60°
- 画角 20〜110°、ロール ±45°。フォーカス: 画質「高」だけ本物の被写界深度（three/examples/jsm の BokehPass。AF は機体までの距離、手動は 2〜2000m（対数）、ボケ 0〜1 = aperture 0〜0.0008、最大ボケ 画面の 1.2%）。「中」「低」はボケなし
- プリセット 6 種（方位 / 仰角 / 距離 / 画角）: 正面 0° / 6° / 24m / 45°・真横 90° / 0° / 32m / 40°・後方上 180° / 25° / 36m / 55°・翼端 120° / 4° / 10m / 75°（注視点を右へ 4m）・見上げ 30° / −35° / 60m / 50°・俯瞰 180° / 80° / 120m / 45°
- 画面の調整（フォトモードの間だけ。出ると元へ）: 露出 ±2EV（レンダラーの露出に掛けるのでどの画質でも効く）・コントラスト 0.5〜1.5・彩度 0〜2・ビネット 0〜1（既定 0.22 = 4-1）・グレイン 0〜1（振幅 0.12）・色温度 −1 暖 〜 +1 寒（RGB × (1.12, 1, 0.84) 〜 (0.88, 0.98, 1.14)）・フィルター なし / フィルム / モノクロ / セピア / 高コントラスト。露出以外は仕上げのパス（トーンマッピング後の表示の色）なので画質「中」以上だけ（「低」は操作できない）
- 表示の切替: HUD（既定は隠す）/ タッチ操作（既定は隠す。出しても触れない）/ 機体 / 敵・怪獣 / エフェクト（弾・ミサイル・爆発・煙・飛行機雲）。機体・敵・エフェクトは Three.js の layers で隠す（影・被写界深度の奥行きからも消える）
- コマ送り: 1 回でゲームの判定を固定ステップ 1 回（1/60 秒）だけ進め、次の描画で演出・機体の描画も 1/60 秒進める（入力は読まず、操作は止めたときのまま）
- 天候・時刻: 7-5 のプリセット 8 種を補間なしで切替、「元に戻す」で元の天候、時刻スライダー 0〜24 時（15 分刻み）。出ると入る前の状態（補間の途中・時間の進行も）へ戻す
- 撮影: レンダラーの出力を PNG（画面サイズ = CSS px / 2 倍 / 4K = 長辺 3840px で縦横比は画面のまま。スマホ（タッチ端末）は 2 倍まで、GPU の上限で切る）。描画バッファを一時的にその大きさにして 1 回描き（表示の大きさは変えない。大きい描画の間はポストエフェクトのマルチサンプルを切る）、2D canvas に写して透かし「SkyRaid」（右下、短辺の 2.8%・余白 2%・不透明度 0.7。撮影パネルの「透かし」で OFF、セーブの設定 `photoWatermark`。版は上げない）。保存はスマホでファイルを共有できれば Web Share API、他は download 属性（`skyraid-YYYYMMDD-HHMMSS.png`）。HUD は DOM なので映らない（WebGL に描く HUD はない）
- UI（4-10 のデザインシステム）: 画面下に横スクロールのツールバー（カメラ / 画面 / 表示 / 天候 / 撮影。右寄せ）、その上にパネル、右下に撮影ボタン（68px、スマホ横画面 60px）、右上に「UI を隠す」「閉じる ✕」。「UI を隠す」で全部消し、画面のダブルタップ（350ms 以内）で戻す

- 音: フォトモード中は効果音をシャッター音（帯域ノイズ 3.2kHz の短い 2 発）だけにし、UI のタップ音も鳴らさない。エンジン・風・雨の環境音はポーズと同じマスター 30% で続く

## 12. データ保存と安全

- フェーズ3まで: localStorage のみ

#### セキュリティヘッダー（4-10。`public/_headers`、Cloudflare Pages の形式）

- Content-Security-Policy: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data: blob:; connect-src 'self' wss://0.peerjs.com; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`。ビルド後に `_headers` を付けて配信し、ヘッドレスのブラウザでタイトル → 飛行 → ポーズまで違反が 0 件なことを確かめた。5-1 で connect-src に PeerJS のシグナリング（`wss://0.peerjs.com`）を足した（STUN は connect-src の対象外）。PvP のロビー → 飛行 → 切断（`?net=local`）でも違反 0 件
- X-Content-Type-Options: nosniff / Referrer-Policy: strict-origin-when-cross-origin / Permissions-Policy: camera・microphone・geolocation・payment・usb を無効 / X-Frame-Options: DENY（`frame-ancestors` を知らない古いブラウザ向け）
- `sw.js` と `manifest.webmanifest` は `Cache-Control: no-cache`（更新をすぐ見つける）
- DOM に文字を入れるのは `textContent` だけ（`innerHTML` は使わない。4-10 でタイトルの 1 か所（固定の文字列）もなくした）。パイロット名・セーブデータの復元の文字列も `textContent` / `value` で扱う

#### セーブデータ（3-1。スキーマは `src/progression/save.ts`、読み書きは `src/progression/save-store.ts`、値は `src/data/save.ts`。Three.js・DOM 非依存）

- localStorage のキー `skyraid.save` に JSON 1 つ: `version`（今は 5）/ `pilotName`（null は未入力）/ `credits` / `missions`（ミッション id → `unlocked`・`bestRank`）/ `aircraft`（`selected` と `owned`: 機体 id → 4 系統の強化 Lv）/ `settings`（`quality`・`qualityAuto`・`touchControls`・`enemies`・`difficulty`・`hud`・`volume`（4-4。`master`・`sfx`・`bgm`、0〜1）・`assist`（4-12。`aim`・`camera`・`hud`、真偽値）・`difficultyEased`（4-11 の事前修正）・`controls`（4-11。`sensitivity`・`deadzone`・`invertPitch`・`autoLevel`・`swapSides`・`vibration`・`buttonSize`・`keys`（アクション → KeyboardEvent.code））/ `flags`（4-11。一度だけの案内: `tutorialOffered`・`tutorialDone`・`hintsFree`・`hintsMission`）
- 読み込み: JSON.parse → 版番号（なければ 0）から `SAVE_MIGRATIONS[版]` を 1 版ずつ通して今の版に → 形と値の確認。骨組み（版・クレジット・ミッション・機体・設定）が違う・JSON でない・未知の新しい版は「壊れている」として初期値で上書きし、画面上部に「セーブデータを初期化しました」を 3 秒（タイトルでも見えるよう HUD の外の要素。見た目は HUD のお知らせと同じ）。細かい不正値（不明なランク・範囲外の強化 Lv・不正な設定）はその項目だけ既定値に直す。移行は v0 → v1 のダミー（版番号なし・`ranks: { id: ランク }` の形。仕組みの確認用）と v1 → v2（3-3: 強化 Lv を 1 下げる（v1 は Lv1 が未強化）・初期機の id `starter` → `kestrel`）と v2 → v3（4-4: 音量を初期値で足す）と v3 → v4（4-12: 操作補助を初期値（すべて ON）で足す）と v4 → v5（4-11: 操作を初期値（今の挙動）で、案内の記録をすべて未表示で足す）。難易度は版によらず、印 `difficultyEased` がなく normal なら一度だけ easy にし、印を立ててすぐ書き戻す（4-11 の事前修正。以後は保存した値のまま）。知らない機体 id は捨てる
- 既存の設定の移行: セーブがないとき、1-6 / 2-3 の別キー（`skyraid.quality` / `skyraid.qualityAuto` / `skyraid.touchControls` / `skyraid.enemies` / `skyraid.difficulty`）を読んでセーブの設定に入れ、保存できたら古いキーを消す。設定の部品（画質・タッチ・敵）は今までどおり古いキー名で読み書きし、`SaveStore.settingsStorage` がセーブの設定に振り分ける
- 保存はイベント駆動: ミッションの終わり（成功の記録・報酬）、設定の変更、パイロット名の決定、ハンガーの操作（3-3）。毎フレームは書かない。localStorage が使えない（プライベートモード等）ときは初期値のまま遊べ、保存だけ失敗する
- 初回起動: セーブにパイロット名がなければタイトルの後に「パイロット名」の入力（8 文字まで。数えるのは見た目の文字（書記素）。制御文字は除き前後の空白を落とす。空なら `PILOT`）。名前はタイトル右下（「PILOT 名前」）とリザルトに出す。入力から Esc でタイトルへ。入力中のキーはゲームの操作（H で HUD など）に渡さない。古い設定を移しただけのときも名前の入力は出す
- チュートリアル（4-11。定義は `src/data/tutorial.ts`、文は `src/data/i18n/*.json` の `tutorial`）:
  - 入り方: モード選択の「チュートリアル」。初回起動はパイロット名を決めた後のモード選択に「チュートリアルを始めますか？」（始める / あとで）を 1 度だけ重ねる（`flags.tutorialOffered`。Esc でも閉じる）
  - 中身はミッションランナーで進める練習のミッション（`practice: true`・失敗条件なし・制限時間なし。キャンペーンの一覧には入れない）。島の北の沖 (0, 900, -3600) から南向きに: ①リング 3 個（直進・左旋回・右旋回、高度 900m）→ ②速度 360 m/s（スロットル最大の 330 では届かずアフターバーナーが要る。目標の種類「速度到達」を足した）→ ③的（風船）2 個（`data/targets.ts` の先頭 2 地点）→ ④ドローン 1 機（1 本目の軌道）→ ⑤敵機 1 機（rookie）。的・ドローン・敵機は既存のもの
  - 練習: 被弾で HP は減るが 1 で止まり撃墜されない（被弾の赤い光は出る）。地面・海面に当たったら墜落にせず、その場の地表から 300m 上空へ戻す（HP・弾はそのまま）
  - 画面上部の中央に「チュートリアル 1 / 5」と短い指示（最初の段階だけ「練習なので撃墜されません…」）と「中断」（モード選択へ）。指示は最後に操作した入力系統で変える（タッチ操作が出ていてパッドを触っていなければタッチ、キーボードは今の割当のキー名を埋める、パッドはボタン名）。段階で使うタッチの部品を黄色く光らせる（①スティック ②スロットル・AB ③GUN ④MSL ⑤GUN・MSL・FLR）。右上の目標の一覧はミッションと同じ
  - 完了: リザルト（「チュートリアル完了」。ランクは出さない。「もう一度」「モード選択へ」）。初めて完了したときだけ 500 CR とセーブの `flags.tutorialDone`。2 回目からは報酬 0。ポーズの「チュートリアルを中断」・指示の「中断」はいつでもモード選択へ
  - ボットの通し（`tests/tutorial.test.ts`。熟練者役・平均的 × 4 シード）: 全部完了、48〜120 秒。人は指示を読むので 3〜4 分の見込み
- タッチ操作のヒント（4-11。`src/ui/touch-hints.ts`）: タッチ操作が出ているとき、フリーフライトとミッション（チュートリアルは除く）のそれぞれ初回だけ、飛行開始の 1 秒後から HUD の速度・高度・レーダー・残弾を順に吹き出しで指す（1 つ 3 秒。ポーズ中は止まる）。出したらセーブの `flags.hintsFree` / `hintsMission` に記録
- エクスポート / インポート（端末を変えるとき）: ポーズメニューの設定の最下部「セーブデータ」に「セーブデータをコピー」（JSON を UTF-8 にして base64。クリップボードに書けないときは文字列を選択状態で出して手動でコピー）と「貼り付けて復元」（欄に貼り付けて「復元する」。空白・改行は無視。読めなければ何も変えずにお知らせ）。復元するとページを読み込み直す
- 削除: その下の「セーブデータを削除」→「進み具合・クレジット・設定がすべて消えます。元に戻せません」と「削除する」「やめる」の 2 段階。削除するとページを読み込み直し、初回起動（パイロット名の入力）から
- フェーズ7以降: Supabase（匿名ログイン + ランキング）。P2Pはチート耐性がないため、ランキングは参考値扱い
