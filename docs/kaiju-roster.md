10-3〜10-5 で足す 3 体の設計と、3 体で共通に使う仕組み（10-2 で作った）。各怪獣のタスクはこれを読んで始める。名前は仮。数値は仮で、各怪獣のタスクのボットの表で決める（ネフィルガの 9-6b〜9-6d と同じ流れ）。

| | ヴォルガス（6-1） | ネフィルガ（9-6） | 白鯨 アルビオン（10-3） | メカ怪獣 ゴウライ（10-4） | UFO ゼノリス（10-5） |
| --- | --- | --- | --- | --- | --- |
| 難しさ | 中 | 中 | 中・長期戦 | 中〜高 | 最高 |
| 戦い方 | 歩いて街へ。部位を選んで撃つ | 空で間合いを取り合う | 大きな的を皆で削る・子分を払う | 弾幕をかいくぐって弱点（後ろ）へ回る | 予兆を読んで避け、隙に撃つ |
| 協力 | ○ | ○ | ◎（協力向き） | ○ | ○ |
| 解放 | 最初から | 最初から | 最初から | 最初から | 条件付き（下の推奨案） |
| 共通の部品 | — | — | 部位・子分 | 部位・弾幕・弾 | 部位・光線・バリア・瞬間移動 |

## 白鯨（アルビオン / Albion）— 10-3

- 一言で: 湾の上空をゆっくり直進する、全長 600m 超の白い鯨。体力がとても多い長期戦。腹の巣から子分を出し続けるので、巣を壊す役と本体を削る役に分かれると速い（協力向き）
- 大きさ: 全長 640m・胴の太さ 110m。高度 700〜900m を 18 m/s で湾の端から端へ（直進して、端で大きく回り返す。周回 1 回 約 4 分）
- 色: 白い肌に灰色の古傷、腹は淡い青灰。巣は腹の 3 か所の赤い裂け目（遠くから「赤い点 3 つ」でわかる）
- 体力: ヴォルガスの約 2.5 倍（ソロ通常）。制限時間 15 分（通常）・12 分（高難度）。失敗は時間切れ（湾を渡り切って去る）
- 失敗の条件・残機: ヴォルガス・ネフィルガと同じ（残機 通常 3・高難度 3、協力は 1 人ずつ）

### 部位（PartSet）

| 部位 | 壊せる | 壊すと |
| --- | --- | --- |
| 腹の巣（前・中・後）× 3 | ○ | その巣から子分が出なくなる（`disable: ['nestFront']` など）。3 つとも壊すと潮吹きの間隔 ×1.3 |
| 背びれ | ○ | 尾の叩きつけの範囲 ×0.7（`mul: { slamRadius: 0.7 }`） |
| 尾びれ | ○ | 尾の叩きつけを使わない・回り返しが大回りに（`disable: ['slam']`） |
| 頭 | ○ | 雲を出さない（`disable: ['cloud']`）。弱点（全体の HP に ×1.5。`bodyFactor: 1.5`） |
| 胴 | × | 全体の HP に効くだけ |

### 子分（MinionSwarm）

- 巣ごとに 20 秒（通常）/ 15 秒（高難度）ごとに 2 匹。同時に 12 匹まで（協力 4 人で 16 匹）。体力 1 発 + α（機銃 6 発・ミサイル 1 発）
- 動き: 巣から下へ散る（1.2 秒）→ 一番近い人へ 150 m/s で寄って周りを回り、近いと体当たり（10）。60 秒で巣へ戻る（撃墜に数えない）
- 撃墜は勲章「子分を 100 匹撃墜した」などに使う（10-3 で足す）

### 攻撃（予兆 / 攻撃 / 硬直の秒数）

1. 真上への潮吹き（2.0 / 1.5 / 1.5）: 予兆は背の噴気孔が膨らんで白く光り、体がわずかに沈む。真上 600m・半径 120m の柱。背の上にいると当たる（40）
2. 尾の叩きつけ（1.6 / 0.6 / 2.0）: 予兆は尾を高く持ち上げて止まる。尾の後ろ 300m の扇に打ち下ろし（50）。後ろについて撃つ人への罰
3. 雲（予兆 2.5 / 20 秒続く）: 予兆は頭の周りに霧が渦を巻く。体の周り 800m に濃い雲（視界が悪くなる。ロックの距離 ×0.6・霧の天候の仕組みを流用）。頭を壊すと出さない
- 攻めどき: 回り返しの間（体を傾けて腹を見せ、巣を狙いやすい）・潮吹きの後の 1.5 秒

## メカ怪獣（ゴウライ / Gourai）— 10-4

- 一言で: 砲台を背負った機械の怪獣。前は厚い装甲、後ろの排気口が弱点。砲台を壊すほど弾幕が薄くなる
- 動き: 推奨案は「低く浮く」（地上 40〜80m をホバリングで滑る。港湾都市の建物の上を越えられ、ヴォルガスの歩きと違う手応えになる）。歩く案は地形と建物との当たりが要る（ほかの案に記録）
- 大きさ: 全長 180m・全高 90m（浮いた状態）。速さ 12 m/s → 後半 30 m/s

### 部位

| 部位 | 壊せる | 壊すと |
| --- | --- | --- |
| 砲台 × 6（左右の肩の機銃 2・背のミサイル 2・腰の機銃 2） | ○ | その砲台は撃たない（Barrage の `part`）。残りの砲台の数で弾幕の厚さが決まる |
| 前の装甲 | × | 当たっても全体の HP に ×0.2（`bodyFactor: 0.2`）。熱がこもると開いて核が出る |
| 核（前） | ○（開いた間だけ当たる） | 弱点（×2.0）。壊すと後半へ |
| 後ろの排気口 × 2 | ○ | 弱点（×1.6）。壊すと熱がこもりやすい（`mul: { heat: 1.5 }`） |

### 攻撃と熱

- 弾幕（Barrage + ShotPool）: 機銃は 1.5〜2.5 秒ごとに 5 連射（広がり 2°・600 m/s・4）、ミサイルは 8 秒ごとに 2 発（260 m/s・40°/秒・20）。砲台ごとに撃てる向きの範囲があり、後ろの下は死角（弱点へ回る道）
- ミサイルの一斉発射（予兆 2.0）: 背のハッチが開いて赤く点滅 → 8 発を扇に。フレアで外れる（ShotPool の decoy）。HUD のミサイル警告（今の仕組み）
- 熱: 撃ち続けると熱がたまり（弾幕 1 回 +4・一斉発射 +15）、100 で 8 秒「放熱」: 装甲が開いて核が見え、砲台が止まる（攻めどき）。排気口を壊すと熱がたまりやすい
- 後半（核を壊すか体力 40% 以下）: 装甲を捨てて速くなる（30 m/s・旋回 ×1.5・弾幕の間隔 ×0.8）。装甲が無いので前からも当たる

## UFO（ゼノリス / Xenolith）— 10-5

- 一言で: 速い銀の円盤。瞬間移動・バリア・光線。いちばん難しいが、予兆を必ず出して理不尽にしない（予兆を見て正しく避ければ当たらない。ネフィルガの 9-6d と同じ決まり）
- 大きさ: 直径 160m・厚さ 30m。速さ 140 m/s（自機の巡航 250 の約半分）で戦域を大きく回る

### 部位

| 部位 | 壊せる | 壊すと |
| --- | --- | --- |
| 縁の発光体 × 4 | ○ | 1 つにつき瞬間移動の間隔 +3 秒。4 つで瞬間移動しない（`disable: ['warp']`） |
| 下の砲口 | ○ | 溜め撃ちを使わない（`disable: ['charged']`） |
| 上のドーム | ○（バリアが外れた間だけ当たる） | 弱点（×1.8） |
| 胴 | ×（バリアが外れた間だけ当たる） | 全体の HP に効くだけ |

### 攻撃（予兆を必ず出す）

1. 瞬間移動（Warp。予兆 1.2）: 移る先が一瞬光る（白い柱と地上の輪）。狙う人から 500m 以上離れた輪の上の所へ。移った直後 1 秒は撃たない
2. バリア（Barrier）: ふだんは張っていて当たらない（当たると青い波紋）。光線の直前に揺らいで（0.6 秒）外れる（4 秒）。外れている間が攻めどき
3. なぎ払う光線（Beam の sweep。予兆 1.5 / 撃つ 1.2 / 硬直 1.0）: 予兆は撃つ線の始めと終わりが薄く光る。方位 ±60° を回す。上か下へ逃げる
4. ロック警告の後の溜め撃ち（Beam の charged。警告 1.5 / 溜め 0.8 / 撃つ 1.2）: 警告の間は狙う人を追い（HUD に「LOCK」と残り秒）、溜めの間は向きが止まる（ここで横へ逃げれば外れる）。当たると 60（一撃で落ちない）
- 段階: 体力 60% から瞬間移動の間隔が短く、30% から溜め撃ちの後に続けてなぎ払う

### 解放の条件（推奨案）

- 「ヴォルガス・ネフィルガ・アルビオン・ゴウライのうち 2 体を通常でクリア」（登録簿の `unlock: { kaiju: [...4 体], count: 2, difficulty: 'normal' }`）
- 理由: 1 体だけだと最初の 2 体で済み「最後の怪獣」の重みが出ない。全部だと好みの合わない怪獣で詰まる。2 体なら最初からいるヴォルガスかネフィルガともう 1 体で届く
- クリアの数え: ソロの自己ベスト（難易度ごと）か、通算の記録の成功（`win.of.raid-<怪獣>`。難易度を分けないので通常の条件だけ）。高難度のクリアは通常にも数える
- ほかの案: (b) どれか 1 体を高難度でクリア（腕前で開く）、(c) 勲章を N 個（遊んだ量で開く）、(d) 条件なし。協力は今は条件を見ない（ホストが選べる）。10-5 で「ホストが解放していなければ選べない」を足すかを決める

## 共通の土台（10-2 で作ったもの）

### 怪獣の登録（`src/data/raid-kaiju.ts` の `RAID_KAIJU`）

1 件に、紹介（画像・英字の名前・攻撃の並び・画像の場面）・名前の文言のキー・記録のキーの形・ランキング・解放の条件・勲章・遅延チャンクの有無・未公開の `?dev=` の名前・協力・街を壊すか・協力の結果の題を持つ。ここから並ぶもの:

| 画面・仕組み | 読むもの |
| --- | --- |
| レイドの怪獣選び（`ui/raid-select.ts`） | 公開されていて（`dev` が null か `?dev=<名前>`）レイドの別の怪獣として登録された怪獣。解放の条件があれば鍵の印・暗い画像・条件の札・出撃のボタンを押せない（`?dev=raid-lock` で見た目を確かめられる） |
| ブリーフィング・結果の題・リプレイ・記録カードの題 | `missions/raid-variants.ts` の登録（`title`・`strings`）。結果の表の部位の名前は `missions/raid-kaiju-hooks.ts` の `partLabels` |
| 協力のロビー | 公開されていて `coop` の怪獣（番号は登録簿の順） |
| ランキング・記録の送信 | `online.ts` の `RANKED_RAID_KAIJU`（登録簿の `ranked`。SQL 0006 の後は「id:難易度」の形の怪獣は全部） |
| 勲章 | レイドのカテゴリの中を登録簿の順に、怪獣ごとに標準の 10 個（クリア・7 分未満・撃墜されず・被弾なし・補助むずかしい × 通常 / 高難度）+ `badges` |
| 画像 | `npm run render-kaiju-art`（登録簿から一覧を読む。未公開は `?dev=` を付ける） |
| 遅延読み込み | `ui/raid-kaiju-link.ts`（`lazy` の怪獣は入口のモジュールが `registerRaidKaijuChunk` で読み方を登録。モード選択・リプレイは id だけで呼ぶ） |

### 共通の部品（`src/ai/raid-kit/`。Three.js 非依存・決まった計算）

- `frame.ts`: 体の基準（位置と方位）と、体に付いた点・向きの計算
- `parts.ts` `PartSet`: 部位の HP（全体の割合）・壊れた効き目（`disable` で攻撃を止める・`mul` で動きの倍率）・弱点 / 装甲（`bodyFactor`）・攻撃した人ごとの与ダメージと破壊（協力の成績）
- `minions.ts` `MinionSwarm`: 巣ごとの出す間隔と数・上限・巣の部位が壊れたら止まる・動き（下へ散る → 狙う人の周りを回る / 体の周り）・寿命・撃墜の数え
- `barrage.ts` `Barrage`: 砲台ごとの位置・撃てる向きの範囲・間隔・連射・広がり・射程・部位。`rate` で熱や後半の速さを掛ける
- `shots.ts` `ShotPool`: 機銃（まっすぐ）とミサイル（追う・フレアに乗り換える）。速い弾のすり抜けを防ぐ当たり
- `beam.ts` `Beam`: なぎ払いと溜め撃ち。予兆・溜めの間は当たらない・溜めの間は向きが止まる・1 回の撃ちで 1 人に 1 回
- `shield.ts` `Barrier`・`Warp`: 揺らいでから外れるバリア、移る先が光ってから移る瞬間移動

決まった計算の決まり: 乱数は渡された種の列（`SeededRandom.next`）だけ、時間は固定ステップの dt の足し算だけ、状態は数・配列のプロパティだけ（関数の中に状態を持たない）。こうするとリプレイのキーフレーム・状態のハッシュにそのまま入る（`tests/raid-kit.test.ts` で、同じ種で同じハッシュ・写して戻すと続きが同じを確かめた）。怪獣の本体はネフィルガの `Kaiju2Raid` と同じく 1 つの根（`GamePlay` の差し込み口の `stateRoot`）に部品をまとめて持つ。

ネフィルガから使ったもの: 部位で動きが変わる考え（翼で速さ ×0.8 → `mul`）・雷球のフレアへの乗り換え（→ `ShotPool` の `decoy`）・攻撃の予兆 / 攻撃 / 硬直の段（→ `Beam` の段）・協力の部位の与ダメージの表（→ `PartSet.damageBy`）。ネフィルガ自身のコードは変えていない（リプレイと状態のハッシュを変えないため。`tests/raid-golden.test.ts`）。

### 協力の同期（`src/net/raid-plugin.ts`・`raid-kit-codec.ts`。通信の版 12）

- 怪獣ごとに `RaidPlugin`（ホストの本体と写し）を登録すれば、`HostGame` が進め、state の怪獣ごとの欄（`raidExtra`）と確実な経路のできごと（`kx`）で配る。`host-game.ts`・`protocol.ts` に怪獣ごとの欄を足さなくてよい（ヴォルガス・ネフィルガは今までの欄のまま）
- 通信を重くしない工夫（推奨案）:
  - 決まった動きは位置を毎回送らない: 弾は「撃った砲台と向き」だけをできごとで送り（1 発 4 バイト）、写しは同じ式でまっすぐ飛ばす。当たりはホストだけが決める（HP の event が来る）
  - 位置を送る子分は飛んでいるものだけ、怪獣の位置からの相対で詰める（1 匹 9 バイト。12 匹で 109 バイト）。多い怪獣は state 2 回に 1 回（7.5Hz）にしてよい
  - 部位は HP の割合を u8 で（部位 8 つで 12 バイト）
  - 目安: 協力レイドの state は今 約 3.1KB/s（ホスト → 1 人）。新しい怪獣も 4KB/s 以下に収める（各怪獣のタスクで `tests/*-coop.test.ts` に帯域の上限を足す）
- 通信の版は 10-2 で 11 → 12（ロビーの「通信の版 12」の表示と、版の違う人が参加したときの「ホストと通信の版が違います」で分かる。古い版の人とは同じ部屋に入れない）。怪獣を足して state の中身が変わっても、差し込み口の中身の形が変わるだけなら版は上げなくてよい。ただし新しい怪獣を足すタスクでは、古い版のアプリがその番号の怪獣を知らない（ヴォルガスとして動いてしまう）ので版を上げる

### 記録のキー

- ヴォルガスは難易度だけ（`normal` / `hard`）、ほかの怪獣は「id:難易度」（`albion:normal` など）
- SQL 0006（`supabase/migrations/skyraid_0006_raid_key_rule.sql`）を流すと、サーバーは「id:難易度」の形（英小文字で始まる 2〜24 文字の id）を全部受け付ける。流した後は怪獣を足しても SQL は要らない。流すまでは登録簿の `ranked` の怪獣だけ送る（今はヴォルガス・ネフィルガ）。手順は README の「レイドの記録のキーの決まり」

### 起動の量

- 新しい怪獣の判定・形・HUD・音・文言は、その怪獣の遅延チャンク（ネフィルガの `kaiju2-runtime` と同じ形）。起動時（タイトルまで）に読むのは何も増やさない。本体（`play-*`）に入るのは登録簿の 1 件と入口のモジュール（ネフィルガの `kaiju2-link.ts` に当たる。数 KB）だけ
- 上限は 10-1 の 320KB（`scripts/startup-budget.js`）のまま

## 怪獣を 1 体足す手順

1. **登録簿**: `src/data/raid-kaiju.ts` の `RAID_KAIJU` の最後に 1 件足す（id・名前のキー・画像・英字の名前・攻撃・画像の場面・`recordKey: 'kaiju'`・`ranked`・`unlock`・`badges`・`lazy: true`・`dev: '<名前>'`（作っている間）・`coop`・`city`・`coopClearKey`）
2. **文言**: `src/data/i18n/ja.json`・`en.json` の `raidSelect.kaiju.<id>`（tagline・size・motion・parts・opening・normal・hard・attacks.<攻撃>.name / note）と、名前・題（ネフィルガの `kaiju2.*` に当たるもの）。判定・HUD だけの文言は遅延チャンクの表に
3. **数値**: `src/data/<怪獣>.ts`（動き・攻撃）と `src/data/<怪獣>-raid.ts`（体力・部位・制限時間）。共通の部品の spec（`PartSpec`・`MinionSpec`・`TurretSpec`・`ShotSpec`・`BeamSpec`・`BarrierSpec`・`WarpSpec`）もここに
4. **判定**: `src/entities/<怪獣>/`・`src/ai/<怪獣>-*.ts` で本体を作り、`src/ai/raid-kit/` の部品を持つ。ソロのレイドは `missions/<怪獣>-raid.ts`（ネフィルガの `kaiju2-raid.ts` の形）と差し込み口（`kaiju2-dev.ts` の形）
5. **ミッション**: `missions/<怪獣>-mission.ts` で `RaidVariant`（ミッション・題・ブリーフィング）を作る
6. **入口**: `ui/<怪獣>-link.ts`（`kaiju2-link.ts` の形）で `registerRaidVariant`・`registerRaidKaijuChunk`・`registerRaidKaijuHooks`（`artAnchor`・`partLabels`）。`game-app.ts` で呼ぶ
7. **描画・HUD・音**: 遅延チャンク（`ui/<怪獣>-runtime.ts`）に。`scripts/vite-chunks.ts` でチャンクを分ける
8. **協力**: `RaidPlugin` を遅延チャンクで `registerRaidPlugin`（ホストは協力の飛行の前に読む）。写しを表示に渡す。通信の版を上げる
9. **勲章**: 登録簿の `badges` に足し、判定（`missions/badges/`）と文言（`badges.*`）を書く。標準の 10 個は自動で並ぶ
10. **画像**: `npm run render-kaiju-art -- <id>`（`public/kaiju-art/<id>.webp`）
11. **公開**: `dev` を null に。changelog と版。ランキングは SQL 0006 を流した後なら何もしない（流す前なら `ranked: true` にする前に SQL を足す）

## ほかの案（10-2 の判断）

- 登録簿を怪獣ごとのファイルに分けて import で集める案: 1 か所に並ぶ方が番号の順（協力の設定の番号）を崩しにくいので、1 ファイルの配列にした
- ヴォルガス・ネフィルガも共通の部品・差し込み口に作り直す案: リプレイと状態のハッシュが変わる（部品の状態の並びが変わる）ので、今回は新しい怪獣だけが使う形にした。作り直すなら、版を分けてリプレイの互換を捨てる判断と一緒に
- 子分・弾の位置を毎回送る案: 子分 16 匹 + 弾 60 発で 1 回 約 900 バイト（15Hz で 13KB/s）になり、4 人のホストの上りが重い
